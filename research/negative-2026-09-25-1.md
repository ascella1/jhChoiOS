## P001. 한국 방문미용/매니큐어 예약시스템 중복예약·취소 관리 혼란

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 방문미용(홈케어), 매니큐어, 마사지 서비스 제공자
- 핵심 문제: 카톡·카카오톡 오픈채팅·당근마켓·숨고 등에서 예약이 동시에 들어오는데, 각 플랫폼의 예약 상태를 일일이 업데이트하지 않으면 "중복 예약" 발생. 고객이 취소하면 수수료는 이미 떨어진 후 보상 규정이 불명확. 특히 당일 취소 시 다른 고객을 끌어올 수 없는 상황 발생
- 사람들이 실제로 싫어하는 것: 숨고에서 예약 확정했는데 카톡으로 같은 시간 다른 예약이 들어와서 한쪽을 취소해야 하는 상황 반복, 취소 수수료 규정이 서비스마다 달라 혼란
- 현재 해결 방법: 수작업으로 각 플랫폼 확인, 예약 확정 메시지를 수동으로 보냄, 구글 캘린더·엑셀 병행
- 발생 빈도: 예약 발생할 때마다 (서비스 제공자 입장에선 하루 3~10건)
- 시간 비용: 일일 수십분 예약 상태 확인·동기화
- 금전 비용: 취소 수수료 규정 불명확로 인한 순수익 악화
- 문제 심각도 (0~10): 5
- 현재 지출: 플랫폼 수수료 15~25%, 별도 관리도구 없음
- 소프트웨어 해결 가능성: 높음 (다중플랫폼 예약 통합 대시보드)
- AI 해결 가능성: 낮음~중간 (중복예약 자동 감지 정도)
- 1인 개발 가능성: 중간 (각 플랫폼 API 연동 필요)

### 실제 근거
- 당근마켓·숨고 서비스 가이드: 예약 취소 정책이 플랫폼별로 다르며 수수료 차감 구조 명시
- 방문미용사 커뮤니티(에펨코리아 자영업판): "여러 채널에서 동시 예약 들어오니 관리가 거의 불가능"이라는 일반적인 토로
- Threads 게시물: 방문 미용 제공자의 일일 예약 관리 스트레스 언급

### 신호 스크리닝
① 정부/공공기관 무료 제공: NO
② 업계 무료 콘텐츠/계산기: NO
③ 기존 SaaS 포함: NO (당근마켓·숨고·카톡은 자체 예약 통합 미지원)
④ 주 1회 이상 반복: YES (매일)
**판정**: 채택 — 방문서비스 제공자의 다중플랫폼 예약 관리 pain

### 왜 중요한 문제인가
배달 문화 확산으로 방문서비스 플랫폼이 다양화되었는데, 제공자 입장에서 모든 플랫폼을 실시간 관리하기는 어렵다. 중복예약으로 인한 신뢰도 저하가 직접 매출에 영향.

### 가정
- 실제 중복 예약 발생 빈도는 통계로 확인하지 못함 (가정: 예약이 많은 제공자일수록 빈번할 것)

### 출처
- 당근마켓·숨고 서비스 정책 페이지
- Threads 방문미용 태그

### 다음 조사 방향
- 실제 방문미용사 커뮤니티 원문에서 구체적 사례 수집
- 현재 사용 중인 예약관리도구(예: Acuity Scheduling 등) 도입 비용 확인

## P002. 한국 온라인 과외 플랫폼 강사 학생별 시간 관리 및 스케줄 충돌

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 과외 플랫폼(숨고, 탈잉, 클래스101 라이브 등) 강사
- 핵심 문제: 여러 학생을 동시에 가르칠 때 "학생 A는 월수금 18:00, 학생 B는 화목금 18:00" 같은 겹치는 시간대가 있는데, 플랫폼에서 자동 스케줄 관리를 지원하지 않아 강사가 수작업으로 예약을 거절해야 함. 특히 수업 시간이 1:1과 1:多(그룹 수업)로 섞여있으면 더 복잡해짐
- 사람들이 실제로 싫어하는 것: "매달 강사님 일정표를 수기로 정리하고, 신청이 들어오면 "이 시간 가능한가?"를 매번 확인하는 번거로움", 시간 충돌로 수업을 거절하면 수입 감소
- 현재 해결 방법: 구글 캘린더·엑셀·카톡으로 수기 관리, 플랫폼 메시지로 "불가능한 시간" 안내
- 발생 빈도: 신청 발생할 때마다 (인기 강사는 주 수십건)
- 시간 비용: 일일 수십분 스케줄 확인·조율
- 금전 비용: 시간 충돌로 거절된 학생으로 인한 잠재 수입 손실
- 문제 심각도 (0~10): 5
- 현재 지출: 플랫폼 수수료 20~40%
- 소프트웨어 해결 가능성: 높음 (플랫폼 내 자동 시간 충돌 감지)
- AI 해결 가능성: 낮음~중간 (충돌 감지 정도)
- 1인 개발 가능성: 중간 (플랫폼 API 연동 또는 크롬 확장 개발)

### 실제 근거
- 탈잉·숨고 강사 커뮤니티: "시간 관리가 수작업이라 효율이 떨어진다"는 언급
- 온라인 강사 커뮤니티(에펨코리아, 카페): "여러 학생 관리하다보면 스케줄이 꼬인다"는 일반적 불만

### 신호 스크리닝
① 정부/공공기관 무료 제공: NO
② 업계 무료 콘텐츠/계산기: NO
③ 기존 SaaS 포함: NO (플랫폼 자체 스케줄 충돌 감지 미지원)
④ 주 1회 이상 반복: YES (매일)
**판정**: 채택 — 온라인 강사의 시간 관리 pain

### 왜 중요한 문제인가
온라인 과외 시장이 성장하면서 강사 수가 증가했는데, 플랫폼이 강사의 스케줄 자동화를 지원하지 않아 수작업 부담 증가.

### 출처
- 탈잉·숨고 강사 커뮤니티
- 에펨코리아 자영업판

- 현재 지출: 전담직원 급여 또는 수동 관리
- 소프트웨어 해결 가능성: 높음 (다중채널 메시지 통합 수신)
- AI 해결 가능성: 중간 (자동 답변 템플릿 제공)
- 1인 개발 가능성: 중간 (각 플랫폼 API 연동)

## P004. 한국 프리랜서 웹디자이너 클라이언트 요청 버전관리 및 최종 파일 확정

- 국가: 대한민국
- 타깃 고객: 웹디자이너·UI/UX 디자이너 프리랜서
- 핵심 문제: 클라이언트가 "색상 변경", "글씨 크기 조정", "레이아웃 수정" 등 피드백을 나누어 여러 번 보낼 때, 디자이너가 각 버전을 추적하기 어렵고 "최종본"이 무엇인지 불명확해짐. 특히 여러 클라이언트를 동시에 처리하면 파일명 규칙이 복잡해져 "이건 어느 프로젝트 몇 버전이더라?"는 상황이 반복됨
- 사람들이 실제로 싫어하는 것: "설계_v1, 설계_v2, 설계_최종, 설계_최종2, 설계_최종_클라이언트수정..." 같은 파일명이 10개 이상 쌓이는 혼란, 클라이언트가 "아, 이건 틀렸어"라고 했을 때 어느 버전으로 돌아가야 할지 불명확

- 시간 비용: 프로젝트당 1~2시간 버전 정리·추적
- 금전 비용: 시간 낭비로 인한 기회비용
- 문제 심각도 (0~10): 4
- 현재 지출: Figma 팀플랜 월정액 또는 무료 버전
- 소프트웨어 해결 가능성: 높음 (버전 자동 추적·diff 제공)
- AI 해결 가능성: 낮음 (버전 관리는 구조적 문제)
- 1인 개발 가능성: 중간 (Figma API 활용)

### 실제 근거
- 디자인 프리랜서 커뮤니티: 버전 관리로 인한 혼란 언급
- 크몽·숨고 디자인 카테고리: 클라이언트 피드백 반영 과정의 복잡성 노출

### 신호 스크리닝
① 정부/공공기관 무료 제공: NO
② 업계 무료 콘텐츠/계산기: NO

- 핵심 문제: 재고 관리 시스템에 기록된 재고와 실제 물리적 재고가 불일치하는 경우 발생 (손상, 도난, 입력 오류 등). 정기적으로 실사를 해야 하는데 수천 개의 SKU를 확인하는 데 수일 소요, 불일치 항목을 찾아 원인을 파악하는 것도 수작업
- 사람들이 실제로 싫어하는 것: "시스템에는 100개가 있다고 하는데 실제로는 85개, 이 15개는 어디 갔는가?", "불일치 항목을 찾는 데 하루 종일 걸린다"
- 현재 해결 방법: 바코드 스캔 후 엑셀 대조, 일부는 RFID·자동화 시스템 도입
- 발생 빈도: 분기별 또는 연 2~4회 정기 실사
- 시간 비용: 1회 실사에 수일 소요 (수천 SKU 기준)
- 금전 비용: 재고 손실, 부정확한 재고로 인한 주문 오류·배송 지연
- 문제 심각도 (0~10): 7
- 현재 지출: 재고 관리 시스템 월정액
- 소프트웨어 해결 가능성: 중간 (실사 데이터 자동 분석·불일치 표시)
- AI 해결 가능성: 중간 (불일치 패턴 분석·원인 제안)
- 1인 개발 가능성: 낮음~중간 (기존 재고 시스템과 통합)

### 실제 근거

- 이커머스 풀필먼트 센터: 재고 오류 비용 언급

### 신호 스크리닝

② 업계 무료 콘텐츠/계산기: NO
③ 기존 SaaS 포함: YES — 재고 시스템이 있으나 실사 자동화는 미흡
④ 주 1회 이상 반복: NO (분기별·연 2~4회, 비정기)

## P017. 글로벌 프로젝트팀 시간대 다른 업무 인수인계 및 커뮤니케이션

- 지역: 전세계
- 국가: 미국·유럽·아시아 등 다국적 팀
- 타깃 고객: 원격 근무 기반 글로벌 팀의 프로젝트 매니저·개발팀
- 핵심 문제: 미국·유럽·아시아 등 여러 시간대의 팀원이 한 프로젝트를 진행할 때 "내가 끝낸 것을 다음 시간대의 팀원이 이어받기"의 과정에서 중요한 정보가 누락되거나 진행 상황이 불명확해짐. 특히 "어디까지 진행됐는가", "다음 단계에서 주의할 점은 뭔가", "블로커는 뭔가" 등의 컨텍스트가 전달되지 않으면 생산성 저하
- 사람들이 실제로 싫어하는 것: "아침에 깨어났는데 해야 할 일이 너무 많아서 어디서부터 시작해야 할지 모르겠다", "어제 뭐가 진행됐는지 알아내는 데 30분을 쓴다"
- 현재 해결 방법: Slack·이메일로 상황 공유, 비동기 메모·노션 문서 작성
- 발생 빈도: 매일 (팀 인수인계)
- 시간 비용: 일일 수십분 컨텍스트 파악
- 금전 비용: 생산성 저하로 인한 프로젝트 지연
- 문제 심각도 (0~10): 5
- 현재 지출: Slack·Notion 등 협업 도구 구독
- 소프트웨어 해결 가능성: 높음 (자동 일일 요약·핸드오프 템플릿)
- AI 해결 가능성: 높음 (Slack·Git 기반 자동 요약)
- 1인 개발 가능성: 높음 (특정 팀 워크플로 자동화)

### 실제 근거
- 글로벌 원격 팀 커뮤니티: 비동기 협업 어려움 언급
- Loom, Twist 등 비동기 커뮤니케이션 도구 성장
- GitLab 비동기 작업 가이드: 명시적 핸드오프의 중요성

### 신호 스크리닝
① 정부/공공기관 무료 제공: NO
② 업계 무료 콘텐츠/계산기: NO
③ 기존 SaaS 포함: YES — Slack·Notion·Loom 등이 부분 해결하나 자동 요약·핸드오프 템플릿 미흡
④ 주 1회 이상 반복: YES (매일)
**판정**: 신중채택 — 이미 Slack·Notion 등으로 부분 해결되고 있으며, 결국 팀의 문화 문제(명시적 커뮤니케이션)가 더 중요할 수 있음. 다만 "자동 일일 요약" 같은 AI 기반 도구는 새로운 니즈. **채택** (변경)

### 왜 중요한 문제인가
글로벌 원격 팀이 증가하면서 비동기 협업의 컨텍스트 손실이 생산성 저하의 주요 원인. 특히 개발팀·데이터팀처럼 복잡한 태스크를 다루는 팀에서 심각.

### 출처
- 글로벌 원격 팀 커뮤니티
- GitLab 비동기 작업 가이드
- Loom, Twist 마케팅

## P018. 글로벌 온라인 튜터 학생별 시간대·시간초과 관리 및 청구

- 지역: 전세계
- 국가: 미국·유럽·아시아 등
- 타깃 고객: Preply, Verbling, iTalki 같은 온라인 튜터링 플랫폼의 튜터
- 핵심 문제: 학생마다 구독 기간(예: 월 5시간), 취소 규정, 시간 이월 여부가 다른데 각 학생의 "남은 시간, 다음 취소 가능 날짜, 시간 이월 만료일"을 추적하기 어려움. 특히 학생이 취소하면 환불을 계산하는 것도 복잡
- 사람들이 실제로 싫어하는 것: "학생 A는 월 5시간인데 6시간을 써버렸다", "학생 B는 환불을 받아야 하는데 계산이 복잡하다", "여러 시간대의 학생을 관리하면서 예약 충돌도 생김"
- 현재 해결 방법: 플랫폼의 자체 추적 기능(일부), 엑셀·구글 캘린더 보조 사용
- 발생 빈도: 매주·매월 (학생별 시간 추적, 취소·환불 처리)
- 시간 비용: 월 3~5시간 학생별 시간·청구 관리
- 금전 비용: 잘못된 청구로 인한 분쟁, 학생 이탈
- 문제 심각도 (0~10): 5
- 현재 지출: 플랫폼 수수료 30~40%
- 소프트웨어 해결 가능성: 높음 (튜터용 통합 관리 대시보드)
- AI 해결 가능성: 중간 (시간 초과 자동 감지·경고)
- 1인 개발 가능성: 중간 (플랫폼 API 또는 독립 앱)

### 실제 근거
- Preply, Verbling 튜터 커뮤니티: 학생별 시간 관리 부담 언급
- iTalki 포럼: 취소·환불 복잡성 불만

### 신호 스크리닝
① 정부/공공기관 무료 제공: NO
② 업계 무료 콘텐츠/계산기: NO
③ 기존 SaaS 포함: YES — 플랫폼 자체에서 기본 추적하나, 복수 플랫폼 사용 시 통합 관리 미흡
④ 주 1회 이상 반복: YES (매주·매월)
**판정**: 채택 — 온라인 튜터의 학생별 시간 관리 pain

## P019. 글로벌 소규모 펀딩사 투자자 리포팅 및 성과 추적

- 지역: 전세계
- 국가: 미국·유럽 중심
- 타깃 고객: VC·엔젤 투자자·펀드 매니저 (관리 자산 수백만~수억 달러)
- 핵심 문제: 투자사(portfolio company)가 10~50개일 때 각 회사의 "최근 재무, 성과, 이슈"를 정기적으로 수집해서 투자자에게 리포팅하는 것이 수작업. 특히 투자사마다 보고 형식·주기·지표가 다르면 표준화된 리포트를 만들기 어려움
- 사람들이 실제로 싫어하는 것: "20개 투자사의 월간 리포트를 매달 수집해서 정리하는 것만 수주일 걸린다", "엑셀로 추적하다 보니 데이터 오류·누락이 발생"
- 현재 해결 방법: 엑셀·구글시트 수작업, 일부는 Carta·Pulley 같은 투자 관리 플랫폼 도입
- 발생 빈도: 월 1회 (월간 리포팅), 분기별 1회 (분기 리포팅)
- 시간 비용: 월 10~20시간 리포트 수집·정리
- 금전 비용: 투자 의사결정 지연 (데이터 준비 시간)
- 문제 심각도 (0~10): 6
- 현재 지출: 투자 관리 플랫폼 월정액(있으면)
- 소프트웨어 해결 가능성: 높음 (자동 리포트 수집·집계)
- AI 해결 가능성: 중간 (성과 분석·예측)
- 1인 개발 가능성: 낮음 (금융 규제·복잡성)

### 실제 근거
- VC 커뮤니티: 투자사 관리 부담 언급
- Carta, Pulley, Recap 같은 투자 관리 플랫폼 성장
- 펀드 매니저 포럼: 리포팅 자동화 수요

### 신호 스크리닝
① 정부/공공기관 무료 제공: NO
② 업계 무료 콘텐츠/계산기: NO
③ 기존 SaaS 포함: YES — Carta·Pulley·Recap 등 존재하나 고가, 소규모 펀드 도입 제한
④ 주 1회 이상 반복: YES (월 1회 최소)
**판정**: 신중채택 — 이미 Carta·Pulley 같은 솔루션이 있으나 가격이 높고 소규모 펀드는 대안 찾음. 저가형 솔루션 여지는 있으나 금융 규제 복잡성 고려하면 **배제** (개발 난이도 높음)

## P020. 글로벌 1인 컨설턴트 클라이언트 프로젝트 기록·비용 추적

- 지역: 전세계
- 국가: 다국적
- 타깃 고객: 전략·마케팅·기술 컨설턴트 프리랜서
- 핵심 문제: 여러 클라이언트 프로젝트를 동시 진행할 때 "프로젝트별 시간 기록, 비용 추적, 청구"를 수작업으로 관리. 특히 프로젝트 중단·재개되거나 스코프 변경되면 "지금까지 몇 시간 썼는가, 남은 예산은 뭔가"를 파악하기 어려움
- 사람들이 실제로 싫어하는 것: "A 프로젝트에 12시간, B 프로젝트에 8시간을 썼는데 타이머 앱이 여러 개면 통합이 안 된다", "청구 시 실제 시간이 계약 시간과 맞는지 확인하기 어렵다"
- 현재 해결 방법: Toggl·Clockify·Harvest 같은 시간 추적 앱, 엑셀 청구서 수기 작성
- 발생 빈도: 매일 (시간 기록), 월 1회 (청구)
- 시간 비용: 월 2~3시간 청구 정산
- 금전 비용: 시간 누락·청구 오류로 인한 손실
- 문제 심각도 (0~10): 4
- 현재 지출: 시간 추적 앱 월정액 $10~30, 청구서 도구 월정액
- 소프트웨어 해결 가능성: 높음 (통합 시간·비용·청구 관리)
- AI 해결 가능성: 중간 (프로젝트 추정 vs 실제 비교)
- 1인 개발 가능성: 높음 (기존 도구 많으나 통합 플랫폼 틈새)

### 실제 근거
- 프리랜서 컨설턴트 커뮤니티: 시간 추적·청구 부담 언급
- Toggl, Clockify, Harvest 사용자 리뷰: 다중 플랫폼 통합 요청
- Slack 독립 컨설턴트 커뮤니티: 청구 자동화 필요성

### 신호 스크리닝
① 정부/공공기관 무료 제공: NO
② 업계 무료 콘텐츠/계산기: NO
③ 기존 SaaS 포함: YES — Toggl, Clockify, Harvest 등 존재하나 각각 부분 해결만 함
④ 주 1회 이상 반복: YES (매일 시간 기록, 월 1회 청구)
**판정**: 신중채택 — 이미 Toggl·Clockify·Harvest 같은 도구가 있고 부분적으로는 해결 중이나, "시간 기록 → 비용 추적 → 청구 자동화"의 전체 흐름 통합은 미흡. 다만 심각도 4 (낮음)이고 이미 충분한 도구가 있어 **배제** (우선순위 낮음)
