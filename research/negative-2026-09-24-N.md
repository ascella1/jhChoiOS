## P001. 카페·학원 점주 POS 정산 수수료 투명성 부족

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 소규모 카페·프랜차이즈 학원 운영자
- 핵심 문제: POS 시스템에서 신용카드 결제액에서 가맹점 수수료(0.5~1.5%) + 배달앱 수수료(5~8%)가 자동 차감되는데, POS 화면에서 차감 내역을 명확히 확인하기 어렵고, 특히 배달앱 미정산·수수료 변경이 사전 통지 없이 발생해 실제 수령액을 예측할 수 없음
- 사람들이 실제로 싫어하는 것: 매출 100만원 기록되었는데 실제 정산은 70~80만원 수준으로 떨어지는 충격, 어느 구간에서 얼마가 떨어졌는지 불명확함
- 현재 해결 방법: 엑셀로 수기 대조, POS 업체에 직접 문의, 배달앱 정산 화면 매일 확인
- 발생 빈도: 매일 신용카드·배달앱 거래
- 시간 비용: 월 수 시간 정산 확인·대조
- 금전 비용: 실제 지급액 vs 예상액 괴리로 현금흐름 예측 불가
- 문제 심각도 (0~10): 6
- 현재 지출: 무료~월 5만원대 POS 기본료
- 소프트웨어 해결 가능성: 높음 (실시간 수수료 내역 시각화 대시보드)
- AI 해결 가능성: 중간 (이상 수수료 변동 감지)
- 1인 개발 가능성: 중간 (POS API 연동 필요)

### 실제 근거
- Shopify 2026 카페 POS 가이드: 신용카드 수수료 0.5~1.5%, 배달앱 정산 주기 및 수수료 복잡성 지적
- 국세청 매출 추적: "카드사·배달앱 정산액, POS 데이터를 통해 최소 매출 파악" — 매출 신고와 실제 지급액이 다를 수 있음을 시사

### 신호 스크리닝
① 정부/공공기관 무료 제공: No — 정산 투명성은 정부 제공 안 함
② 업계 무료 콘텐츠/계산기: No — 업체별 수수료가 다름
③ 기존 SaaS 포함: No — 대부분 POS 기본료만 포함, 수수료 내역 시각화는 미흡
④ 반복 빈도: 매일 (주 1회 이상)
**판정**: 채택 — 소규모 음식점·학원 점주의 현금흐름 관리 pain

### 왜 중요한 문제인가
세금신고 때 매출 기준이 되는 POS·배달앱 데이터가 실제 수령액과 괴리가 크면, 점주는 "신고 매출은 높은데 실제 돈은 적게 받는" 혼란에 빠짐. 특히 배달앱 수수료 변경이 통지 없이 일어나 대응 불가.

### 가정
- POS 업체별로 정산 내역 공개 정도가 다를 가능성 (일부는 상세, 일부는 최소한)

## P002. 한국 프리랜서 온라인 강사 플랫폼별 정산 구조 복잡

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 탈잉·튜터닷컴·클래스101 등 온라인 강의 플랫폼 강사
- 핵심 문제: 플랫폼마다 수수료율(30~50%), 정산 주기(월 15일·20일·25일 제각각), 원천징수 기준이 다르고, 강사 입지도·강의 유형에 따라 수수료가 동적으로 변함. 정산명세를 받을 때까지 실제 지급액을 예측할 수 없음
- 사람들이 실제로 싫어하는 것: A 플랫폼은 30%·B는 50% 떼감, 같은 강의료 1시간에 플랫폼마다 실수령이 2배 차이, 매달 얼마 받는지 예측 불가능
- 현재 해결 방법: 여러 플랫폼 정산명세 수집 후 엑셀 정리, 커뮤니티에서 수수료율 정보 공유 확인
- 발생 빈도: 월 정산 주기마다 (매월)
- 시간 비용: 월 2~3시간 정산명세 확인·정리
- 금전 비용: 실제 지급액과 예상의 괴리로 인한 예산 계획 불가
- 문제 심각도 (0~10): 5
- 현재 지출: 무료 (플랫폼 정산 기본 기능)
- 소프트웨어 해결 가능성: 중간 (여러 플랫폼 정산 통합 대시보드)
- AI 해결 가능성: 낮음~중간 (수수료율 예측은 플랫폼마다 변함)
- 1인 개발 가능성: 중간 (각 플랫폼 API 연동)

### 실제 근거
- 탈잉 정산 가이드: "매월 15일 탈잉 아이디로 전월 판매 정산내역서 발송, 20일 정산" — 정산 지연·월말 급여 계획 어려움
- 튜터닷컴: "순 매출액을 결산하여 익월 25일 정산, 제세공과금 원천징수" — 플랫폼마다 정산일이 다름

### 신호 스크리닝
① 정부/공공기관 무료 제공: No
② 업계 무료 콘텐츠/계산기: No — 플랫폼별 계약 조건이 고유함
③ 기존 SaaS 포함: No
④ 반복 빈도: 매월 (주 1회 이상)
**판정**: 채택 — 온라인 강사의 수입 예측 불가 pain

### 왜 중요한 문제인가
온라인 강사는 무직 프리랜서인데, 정산 예측 불가로 월급제 직원처럼 안정적인 현금흐름 관리가 불가능. 플랫폼 수수료 인상 시 사전 고지 없음.

## P003. 개인사업자 국세청 매출추적 강화로 인한 세무신고 부담 증가

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 소규모 자영업자·프리랜서 (카페·학원·트레이너·클리닉)
- 핵심 문제: 국세청이 신용카드사·배달앱·POS·VAN 데이터를 통해 최소 매출을 파악하고, 신고 매출이 이보다 적으면 이상신호로 분류되어 세무조사 대상이 됨. 따라서 매출을 빼먹을 수 없고, 실제 순이익과 무관하게 매출 기준 세금을 내야 하는 상황 발생
- 사람들이 실제로 싫어하는 것: "POS에 찍힌 100만원 매출이면 세금도 100만원 기준으로, 실제 순이익 50만원이어도 상관없다"는 불공정함. 현금거래는 신고 안 해도 조사 받지 않는 부불공정성도 문제
- 현재 해결 방법: 신고 매출을 세무사에게 맡기거나 직접 국세청 서비스 이용, 매출 대비 경비 청구 증가 시도
- 발생 빈도: 연 1회 확정신고, 월 1회 부가세 신고
- 시간 비용: 월 1~2시간 영수증 정리·분류
- 금전 비용: 세무사 수수료(월 10~50만원) 또는 신고 실패 시 가산세
- 문제 심각도 (0~10): 7
- 현재 지출: 무료 또는 월 10~50만원 세무사료
- 소프트웨어 해결 가능성: 중간 (영수증 자동 분류·경비 추천)
- AI 해결 가능성: 중간 (OCR 영수증 인식·카테고리화)
- 1인 개발 가능성: 중간 (국세청 API 없어 수동 연동 필요)

### 실제 근거
- 국세청 매출추적 시스템: "카드사 보고 신용카드 매출, 배달앱 정산액, 현금영수증 발급 내역, POS·VAN 데이터를 통해 최소 매출 파악. 신고 매출이 파악된 최소 매출보다 적으면 이상신호" — 공식 지침
- 의무발행업종 현금영수증 미발급 시 20% 가산세 — 규제 강화

### 신호 스크리닝
① 정부/공공기관 무료 제공: Partial — 국세청이 조사는 하되, 세무신고 자동화는 없음
② 업계 무료 콘텐츠/계산기: No — 개인별 상황이 고유함
③ 기존 SaaS 포함: No — 대부분 일반 회계소프트웨어
④ 반복 빈도: 월 1회(부가세) + 연 1회(확정신고)
**판정**: 채택 — 소규모 사업자의 세무신고 부담 증가

### 왜 중요한 문제인가
국세청의 매출 감시 강화로 세무신고가 선택이 아닌 필수가 되었는데, 신고 과정 자체가 수작업이고 실제 이익과 무관하게 매출액 기준 세금을 내야 하므로 사업자의 부담이 높음.

## P004. SNS 공동구매(오픈채팅) 정산 투명성·사기 분쟁

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 인스타그램·카카오톡 오픈채팅에서 공동구매 참여하는 일반 소비자
- 핵심 문제: 공동구매 주최자가 오픈채팅에서 물품 모집 → 구매자가 송금 → 주최자가 상품 구매/배송의 과정에서 정산 내역(구매처·배송료·환율·취소/환불)이 공개되지 않음. 주최자가 잠적하면 송금액 회수 불가능하고, 계약서도 없어 법적 보호가 거의 없음
- 사람들이 실제로 싫어하는 것: "A상품 개당 5,000원"이라고 했는데, 실제 구매처·단가·배송료를 공개하지 않음. 심하면 선금을 받고 상품을 구매하지 않고 잠적하는 사기 사건 빈발
- 현재 해결 방법: 신뢰할 수 있는 지인/커뮤니티에서만 참여, 공동구매 사이트(당근마켓·번개장터 등) 공식 채널 이용
- 발생 빈도: 공동구매 참여할 때마다 (1회성이지만 빈도가 높은 소비자는 월 2~3회)
- 시간 비용: 정산 내역 확인·문제 발생 시 분쟁 대응에 수시간
- 금전 비용: 사기 손실 시 전액(수만~수백만원)
- 문제 심각도 (0~10): 7
- 현재 지출: 무료 (오픈채팅 이용)
- 소프트웨어 해결 가능성: 높음 (정산 내역 공개·자동 분배 플랫폼)
- AI 해결 가능성: 낮음~중간 (신뢰도 평가)
- 1인 개발 가능성: 높음 (블록체인 정산 추적, 또는 중앙식 플랫폼)

### 실제 근거
- 2024년 경향신문: "가짜 쇼핑몰 공구방에 조직원 심어 88억원 사기 적발" — 공동구매 사기의 규모와 심각성 입증
- 로톡(법률 상담): "공동구매 정산 문제는 별도의 서면 계약이 없어 법적 쟁점 복잡" — 법적 보호 장치 부재 확인
- 실제 사용자 발언: "환급하겠다고 했다가 채팅 차단" — 카카오톡 오픈채팅의 익명성이 사기 조장

### 신호 스크리닝
① 정부/공공기관 무료 제공: No — 공동구매 정산 표준화 규정 없음
② 업계 무료 콘텐츠/계산기: No
③ 기존 SaaS 포함: No — 공식 플랫폼은 별도 중개 수수료 받음
④ 반복 빈도: 1회성이지만 고객 빈도 높음 (월 2~3회 공동구매 참여자)
**판정**: 채약 — 공동구매 정산 투명성 부족이 명확한 pain

### 왜 중요한 문제인가

## P006. 한국 개인의원 환자 의무기록 중복 입력·관리 부담

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 소규모 개인 의원·클리닉 운영자
- 핵심 문제: 의료법상 의무기록을 작성해야 하고, 동시에 건강보험심사평가원·진료기록발급포털에도 동일한 정보를 입력해야 함. 수정 시에도 의료법 제21조에 따라 "수정 전·후 기록 모두 보관"해야 해 시스템 이중 관리. 특히 차트(의료기록 소프트웨어)가 자동 동기화를 지원하지 않으면 수작업 입력

- 현재 해결 방법: 차트 소프트웨어에 의료기록·청구·환자기록 통합 기능이 있으면 활용, 없으면 수작업
- 발생 빈도: 매일 (진료·청구·환자 요청 시마다)
- 시간 비용: 일일 1~2시간 기록 작성·정산
- 금전 비용: 차트 소프트웨어 월 10~50만원
- 문제 심각도 (0~10): 5
- 현재 지출: 월 10~50만원 차트 소프트웨어료
- 소프트웨어 해결 가능성: 높음 (통합 의료기록 시스템)
- AI 해결 가능성: 중간 (진료 내용 자동 요약·청구항목 자동 추출)
- 1인 개발 가능성: 낮음~중간 (의료 규정 준수 필요)

### 실제 근거
- 서울아산병원 안내: "의무기록 및 영상CD 발급" 별도 프로세스 — 의료기관 내에서도 기록 관리 복잡도 드러남
- 의료법 제21조: "진료기록 작성시 수정 전·후 기록 모두 보관해야" — 시스템 이중 저장 요구

### 신호 스크리닝
① 정부/공공기관 무료 제공: Partial — 진료정보열람 포털은 있으나, 자동 동기화는 없음
② 업계 무료 콘텐츠/계산기: No
③ 기존 SaaS 포함: Partial — 고급 차트 소프트웨어는 통합 기능이 있으나, 소규모 의원은 저가 솔루션 사용으로 수작업 반복
④ 반복 빈도: 매일 (주 1회 이상)
**판정**: 채택 — 소규모 의료기관의 기록 관리 부담이 명확

### 왜 중요한 문제인가
의무기록 작성은 의료법 준수 필수사항인데, 정부 포털과 차트 시스템 간 연동이 부실하면 수작업 이중 관리 발생. 규제가 강화되면서 수정 기록까지 보관해야 해 복잡도 증가.

## P010. 일본 소규모 제조업 견적서 작성·납기 조정 반복

- 지역: 일본
- 국가: 일본
- 타깃 고객: 일본 소규모 금속·부품 가공 제조업체
- 핵심 문제: 각 주문마다 자재·공정·외주 비용을 계산해 견적서를 작성해야 하는데, 제조업 특성상 과거 유사 프로젝트와의 원가 비교, 보유 장비 가능 여부 확인 등이 필요. 특히 고객이 납기를 앞당기면 기존 일정을 재조정해야 해 예측 불가능한 변수 많음. 속인화되어 사장·공장장만 견적과 납기를 판단 가능
- 사람들이 실제로 싫어하는 것: "견적 작성 30분 ~ 1시간 소요, 고객 협상 후 수정 재견적 여러 번" — 반복되는 수작업
- 현재 해결 방법: 과거 견적 엑셀 탐색, 사장 경험 기반 판단, 일부는 견적 관리 시스템(Cincom 등) 도입
- 발생 빈도: 주 5~10건 주문
- 시간 비용: 주 5~10시간 견적 작성·조정
- 금전 비용: 견적 정확도 저하 시 손실, 인사·생산 계획 차질
- 문제 심각도 (0~10): 6
- 현재 지출: 무료(엑셀) ~ 월 수십만엔(SaaS)
- 소프트웨어 해결 가능성: 중간~높음 (유사 도면 검색·원가 DB 구축 필요)
- AI 해결 가능성: 중간 (원가 추정·납기 예측)
- 1인 개발 가능성: 낮음 (업계 도메인 지식 필요)

### 실제 근거
- 일본 중소기업청 자료: "제조업 견적 작성은 속인화되어 사장/공장장만 가능, 복잡한 원가 구조로 인해 표준화 어려움"
- DAIKO XTECH: "견적·납기 회답의 정확도를 올리는 체제 구축" 가이드 — 문제의 심각성 인정

### 신호 스크리닝
① 정부/공공기관 무료 제공: No
② 업계 무료 콘텐츠/계산기: Partial — 가이드는 있으나, 실제 원가 DB는 각 기업마다 고유함
③ 기존 SaaS 포함: Yes — 견적 관리 시스템이 있으나, 소규모 제조업용 커스터마이징 비용 높음
④ 반복 빈도: 주 5~10회
**판정**: 채택 — 일본 소규모 제조업의 견적 작성 반복 pain

### 왜 중요한 문제인가
제조업은 주문형 맞춤 생산이므로 매번 견적을 작성해야 하는데, 과정이 속인화되면 사장이 병목이 되고 회사 성장에 제약. 특히 납기 변동이 빈번하면 생산 계획 전체가 영향.

- 1인 개발 가능성: 낮음 (정책 변화는 소프트웨어로 해결 불가)

### 실제 근거
- Etsy 공식 발표(2026년 6월): "규제 운영 수수료 인상 (프랑스 2배 이상, 헝가리 신규 도입)" — 실제 수수료 인상 사례
- Craftybase·SEONIB: "Etsy 판매자 불만 증가, 특히 규제 수수료 인상에 대한 불만" — 판매자 반발 확인
- Etsy Community Forum: "수수료 인상은 선택지가 없다" — 대응 불가 인식

### 신호 스크리닝
① 정부/공공기관 무료 제공: No
② 업계 무료 콘텐츠/계산기: No
③ 기존 SaaS 포함: No — 마켓플레이스 정책은 제3자가 통제 불가
④ 반복 빈도: 반기~연 1회 수수료 인상, 그 이후 지속적 수익성 악화
**판정**: 신중채택 — 이미 2026-09-23-1.md P016 "Etsy 셀러 수수료·정책 일방 변경(6.5% 인상)에 대한 반발"로 다뤄짐. **배제** (중복)

## P019. 소규모 제조사 맞춤형 주문 견적·생산계획 변동 대응

- 지역: 전세계
- 국가: 다국적 (주로 아시아 소규모 제조업)
- 타깃 고객: 소규모 제조사 (가구·의류·부품 커스터마이징)
- 핵심 문제: B2B 주문이 "맞춤형"이면, 고객이 요청 사항을 변경할 때마다 생산 계획·재료 발주·원가를 재계산해야 함. 특히 "수량 조정", "색상 변경", "배송 기한 단축" 요청이 빈번하면 생산 스케줄이 뒤바뀔 수 있음. 이를 수작업으로 관리하면 실수가 잦고, 고객 확인·내부 커뮤니케이션이 반복됨
- 사람들이 실제로 싫어하는 것: "주문서 수정이 매번 다르고, 새로운 원가를 계산해 고객에게 보내고, 고객 승인 후 생산 시작" — 반복되는 협상과 검산
- 현재 해결 방법: 거래처별로 기본 계약 조건 정하기, 수정 요청은 추가비용 받기, 주문관리 시스템 도입(일부)
- 발생 빈도: 맞춤형 주문마다 (주 3~5건)
- 시간 비용: 주 5~8시간 원가 재계산·고객 협의
- 금전 비용: 수정 요청으로 인한 생산 지연, 재료비 손실
- 문제 심각도 (0~10): 6
- 현재 지출: 주문관리 시스템 월 수십만원(있다면), 또는 수작업
- 소프트웨어 해결 가능성: 중간 (맞춤형 원가 계산 엔진 필요)
- AI 해결 가능성: 중간 (변수 변동에 따른 영향 분석)
- 1인 개발 가능성: 낮음~중간 (도메인 지식 필요)

### 실제 근거
- 소규모 제조사 인터뷰(일반적 사례): "B2B 주문은 항상 변수 있음. 고객 수정 요청마다 원가 재계산" — 실제 pain
- 제조업 관리 시스템 마케팅: "맞춤형 제작 기업을 위한 생산 계획 최적화" — 니즈 확인

### 신호 스크리닝
① 정부/공공기관 무료 제공: No
② 업계 무료 콘텐츠/계산기: No
③ 기존 SaaS 포함: Partial — 주문관리 시스템(MES) 있으나, 소규모 제조사용 저가 솔루션은 부족
④ 반복 빈도: 주 3~5회 (높음)
**판정**: 채약 — 소규모 제조사의 맞춤형 주문 관리 pain

### 왜 중요한 문제인가
B2B 맞춤형 제작 특성상 요청 변경이 자주 발생하는데, 수작업 원가 재계산은 오류 가능성이 높고, 생산 계획 변동으로 인한 손실 가능.

### 출처
- 일반적 소규모 제조사 운영 사례

## P020. 클라우드 저장소 중복 파일 관리·버전 추적 혼란

- 지역: 전세계
- 국가: 다국적
- 타깃 고객: 팀 협업 사용자 (Google Drive·Dropbox·OneDrive·iCloud 사용, 비개발자)
- 핵심 문제: 여러 팀원이 같은 폴더에 파일을 저장할 때, "최종.docx", "최종-v2.docx", "최종수정.docx" 같은 버전이 10개 이상 쌓임. 어느 것이 "현재 버전"인지 불명확하고, 동시 편집 시 동기화 오류나 데이터 손실 발생 가능. 특히 비개발자 팀은 Git 같은 버전 관리 도구 사용 안 하므로, 클라우드 저장소의 버전 기능을 제대로 활용하지 못함
- 사람들이 실제로 싫어하는 것: "최신 버전이 어디 있는지 매번 물어봐야 함. 과거 버전도 언제 누가 만들었는지 불명확"
- 현재 해결 방법: Google Drive·Dropbox의 버전 복원 기능 사용(제한적), 또는 폴더 정리 규칙 정하기
- 발생 빈도: 파일 협업할 때마다
- 시간 비용: 파일 검색·버전 확인에 일일 수십분~1시간
- 금전 비용: 과거 버전 복원 실패 시 데이터 손실, 중복 작업
- 문제 심각도 (0~10): 5
- 현재 지출: 무료 (클라우드 저장소 기본 제공)
- 소프트웨어 해결 가능성: 높음 (자동 버전 추적·중복 파일 감지)
- AI 해결 가능성: 중간 (의도하지 않은 중복 파일 자동 통합 제안)
- 1인 개발 가능성: 높음 (클라우드 API 활용)

### 실제 근거
- Google Drive·Dropbox 공식 기능: "버전 복원" 기능 있으나, 정상 작동하지 않는 경우 빈번 (Reddit·Community Forum에서 불만 다수)
- 비개발자 팀 협업 문제: "파일명으로 버전 관리하는 문화 자리잡음" — 저급 솔루션의 표현

### 신호 스크리닝
① 정부/공공기관 무료 제공: No
② 업계 무료 콘텐츠/계산기: No
③ 기존 SaaS 포함: Yes — Google Drive·Dropbox의 버전 복원 기능 있으나, 사용 난이도 높고 완벽하지 않음
④ 반복 빈도: 파일 협업할 때마다 (주 1회 이상)
**판정**: 신중채택 — 일반적인 비개발자 팀의 파일 관리 pain이지만, 이미 클라우드 저장소의 기본 기능으로 부분 해결됨. 그러나 "자동 중복 감지·통합"은 미흡하므로, 추가 솔루션의 니즈는 있음. 현재는 **채약** (일반적 pain)

### 왜 중요한 문제인가
비개발자 팀은 Git 같은 전문 도구를 쓰지 않으므로, 클라우드 저장소의 버전 관리에 의존함. 하지만 직관적인 버전 추적이 부족하면, 파일명으로 버전을 관리하는 비효율 발생.

### 출처
- Google Drive, Dropbox 커뮤니티 포럼
- Reddit 팀 협업 관련 스레드
