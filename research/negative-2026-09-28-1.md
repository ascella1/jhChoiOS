## P001. 온라인 쇼핑 반품 배송비 부담 및 환불 지연

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 온라인 쇼핑 이용자, 의류·신발 구매자
- 핵심 문제: 온라인으로 구매한 상품(주로 의류, 신발)이 맞지 않거나 불량이면 반품해야 하는데, 배송사별·판매처별로 반품 규정이 다름. 일부는 소비자가 배송비를 부담하고, 일부는 판매자 부담. 반품 신청부터 환불 완료까지 평균 5~10일이 소요되지만, 중간에 정산 지연으로 더 길어지는 경우 다수
- 사람들이 실제로 싫어하는 것: "반품 배송비가 5,000~10,000원인데, 반품하는 게 손실", "반품 신청했는데 환불이 3주 걸림", "일부 판매자는 반품을 거부하거나 불량 판정을 따지는 경우 있음"
- 현재 해결 방법: 판매자에게 전화 또는 카톡으로 반품 신청, 배송사 안내에 따라 반품, 금융감독원이나 소비자센터 신고
- 발생 빈도: 월 1~2회 (반품 필요 시)
- 시간 비용: 반품 절차에 30분~1시간
- 금전 비용: 반품 배송비 월 0~2만원
- 문제 심각도 (0~10): 5
- 현재 지출: 월 3만~20만원 (온라인 쇼핑)
- 소프트웨어 해결 가능성: 높음 (반품 배송비 자동 계산 및 선택형 반품)
- AI 해결 가능성: 중간 (환불 규정 자동 해석)
- 1인 개발 가능성: 중간 (배송사 API 연동)

### 실제 근거
- 쿠팡: "반품 배송료 지원 정책" — 일부 상품만 배송료 지원, 소비자 부담 많음
- 무신사: "반품 안내" — 배송료 정책이 상품·판매자별로 상이
- 소비자 커뮤니티: "온라인 반품 배송료 때문에 반품 포기하는 이유"

### 신호 스크리닝
① 정부 무료 제공: No — 정부가 반품 프로세스 자동화를 제공하지 않음
② 업계 무료 콘텐츠: No — 각 판매처·배송사별로 다른 규정
③ 기존 SaaS 포함: No — 통합 반품 관리 플랫폼 부재
④ 반복 빈도: 월 1~2회

**판정**: 채택 — 온라인 쇼핑 이용자의 반복적 pain

### 왜 중요한 문제인가
온라인 쇼핑 이용자가 월 1~2회 반품할 때마다 배송비 부담, 환불 지연, 판매자 분쟁 등을 겪음. 반품 프로세스 자동화가 있으면 시간 절감 및 비용 절감 가능.

### 가정
- 배송사·판매처 API 연동 가능성 확인 필요

### 출처

- https://www.musinsa.com/

## P002. 카풀·택시 예약 후 기사 취소로 인한 시간 낭비

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 출퇴근 직장인, 기다릴 시간이 없는 사용자
- 핵심 문제: 카풀 앱(카카오맵, 네이버맵, 타다 등)이나 택시 호출 앱에서 승차를 예약했는데, 기사가 뜬금없이 취소하는 경우가 빈번. 한 번 취소되면 다시 호출해야 하고, 여러 번 취소되는 경우도 있어 심각한 시간 낭비. 규칙적으로 발생하지만 기사에 대한 페널티가 미흡
- 사람들이 실제로 싫어하는 것: "기사가 최종 목적지를 보고 취소해버림", "30분 후 출발 예약했는데 10분 전에 취소", "연속 취소로 인해 지각하는 일이 발생"
- 현재 해결 방법: 카풀/택시 앱에서 다시 호출, 복수 호출 (여러 앱 동시 호출), 대중교통으로 변경
- 발생 빈도: 주 1~2회 (정규 카풀/택시 이용자 기준)
- 시간 비용: 취소마다 5~15분 지연
- 금전 비용: 없음 (환불됨)
- 문제 심각도 (0~10): 6
- 현재 지출: 월 10만~30만원 (카풀·택시 이용료)
- 소프트웨어 해결 가능성: 높음 (기사 신뢰도 평가 및 취소 페널티 강화)
- AI 해결 가능성: 중간 (취소 위험 기사 미리 필터링)
- 1인 개발 가능성: 낮음 (기사 네트워크 필요)

### 실제 근거
- 카카오맵/네이버맵: "기사 취소" 관련 사용자 불만 게시물 다수
- 타다 사용자 커뮤니티: "기사 취소로 인한 지각 경험담"
- 소비자 센터: "카풀·택시 기사 취소 관련 민원" 증가

### 신호 스크리닝
① 정부 무료 제공: No
② 업계 무료 콘텐츠: No
③ 기존 SaaS 포함: Partial — 앱들이 취소 페널티가 있지만, 실제로는 미흡
④ 반복 빈도: 주 1~2회

**판정**: 채택 — 직장인의 명확한 pain signal

### 왜 중요한 문제인가
카풀·택시 이용자가 주 1~2회 기사 취소로 인한 시간 낭비를 경험. 신뢰도 높은 기사 매칭이 있으면 만족도 향상.

### 가정
- 기사 취소 실제 빈도 정량화 필요

- https://map.naver.com/

## P003. 공과금 자동이체 계좌 변경 시 서비스사별 개별 신청

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 금융 계좌 변경자, 이사·혼인으로 계좌 변경하는 사람
- 핵심 문제: 통상 계좌를 변경하려면 (예: 이사, 은행 변경, 혼인 후 남편 계좌로 통일) 각 공과금 서비스사(전기, 수도, 가스, 인터넷, 보험 등)에 개별적으로 연락하거나 웹사이트에 방문해서 계좌 변경 신청을 해야 함. 이 과정이 서비스사별로 상이하고, 일부는 전화·팩스·우편 신청만 가능
- 사람들이 실제로 싫어하는 것: "10개 회사에 각각 전화해서 계좌 변경 신청해야 함", "일부 회사는 온라인 변경이 안 되고 방문이나 전화만 가능", "변경 후 한두 달 후에 이전 계좌로 청구서가 나오는 경우도 있음"
- 현재 해결 방법: 각 서비스사 웹사이트 또는 고객센터에 개별 신청, 은행에서 "자동이체 변경" 서비스 이용 (제한적)
- 발생 빈도: 수년에 1회 (계좌 변경 시)
- 시간 비용: 계좌 변경에 월 1~2시간 (여러 회사 연락)
- 금전 비용: 없음
- 문제 심각도 (0~10): 4
- 현재 지출: 무료
- 소프트웨어 해결 가능성: 높음 (공과금 계좌 통합 변경 플랫폼)
- AI 해결 가능성: 중간 (자동 양식 입력)
- 1인 개발 가능성: 낮음~중간 (각 서비스사 API 필요)

### 실제 근거
- 한국은행: "자동이체 변경 절차" — 개별 서비스사 신청 필요함을 명시
- 이사 커뮤니티: "이사 후 해야 할 일 리스트" — 공과금 계좌 변경이 가장 번거로운 항목
- 금융감독원: "공과금 변경 관련 민원" 소수 존재

### 신호 스크리닝
① 정부 무료 제공: No
② 업계 무료 콘텐츠: No
③ 기존 SaaS 포함: No
④ 반복 빈도: 수년에 1회 (낮은 빈도)

**판정**: 신중채택 — 빈도가 낮지만, 일회성 pain이 높음

### 왜 중요한 문제인가
이사나 계좌 변경 시 여러 회사에 개별 신청하는 것은 번거로움. 그러나 수년에 1회 정도이므로 SaaS 비즈니스 모델로 지속 수익 확보 어려움.

### 가정

## P004. 직장인 점심 식사 예약 플랫폼 이중예약 문제

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 직장인, 사무직 직원
- 핵심 문제: 점심 시간이 정해진 회사에서 직원들이 예약 사이트(배민, 다이닝코드, 점메뉴 등)에서 식당을 예약했는데, 같은 시간에 같은 식당 예약이 중복되어 식당이 수용하지 못하는 경우 발생. 예약 시스템이 식당별 테이블 수를 실시간으로 반영하지 못하거나, 예약 취소가 제때 반영되지 않는 문제
- 사람들이 실제로 싫어하는 것: "점심 시간에 예약했는데 식당에 가보니 자리가 없음", "2개 앱에서 예약했는데 둘 다 확정되어서 한쪽을 취소해야 함", "예약 시간이 지났는데 식당이 아직도 예약으로 표시되어 있음"
- 현재 해결 방법: 다이닝코드, 배민, 점메뉴 등에서 테이블 현황 수동 확인, 여러 앱에 동시 예약 후 하나 취소, 직장 근처 식당에 전화 예약
- 발생 빈도: 주 3~5회 (점심 예약)
- 시간 비용: 식당 찾기 및 예약에 10~20분, 이중예약 시 추가 10분
- 금전 비용: 없음 (예약 취소 가능)
- 문제 심각도 (0~10): 5
- 현재 지출: 월 50만~100만원 (점심 식사)
- 소프트웨어 해결 가능성: 높음 (식당 테이블 실시간 동기화 및 단일 예약 시스템)
- AI 해결 가능성: 높음 (개인 선호도 기반 식당 추천)
- 1인 개발 가능성: 중간 (식당 예약 시스템 연동)

### 실제 근거
- 배민: "테이블 예약" 서비스 운영 중 — 이중예약 문제 보고 다수
- 다이닝코드: "식당 테이블 현황" — 실시간 업데이트 지연 현상
- 직장인 커뮤니티: "점심 예약 앱 추천" 관련 이중예약 불만

### 신호 스크리닝
① 정부 무료 제공: No
② 업계 무료 콘텐츠: No
③ 기존 SaaS 포함: Yes — 배민, 다이닝코드, 점메뉴 등
④ 반복 빈도: 주 3~5회

**판정**: 신중채택 — 기존 경쟁사가 있지만, 이중예약 문제는 아직 해결되지 않음

### 왜 중요한 문제인가
직장인이 주 3~5회 점심 예약할 때 이중예약·부재석·테이블 부족 문제를 경험. 통합 예약 시스템이 있으면 시간 절감.

### 가정
- 식당의 예약 시스템 API 개방 여부 확인 필요

- 금전 비용: 없음 (추적 무료)

## P014. 글로벌 직장인 경비 보고서 자동 분류 및 영수증 OCR

- 국가: 다국가
- 타깃 고객: 글로벌 직장인, 경영진, 경비 관리자
- 핵심 문제: 글로벌 회사에서 직원들이 출장 경비를 보고할 때, 영수증을 스캔해서 올리고, 경비 관리자가 이를 일일이 검토·분류하는 것이 수작업. OCR 기술로 자동 인식할 수 있지만, 다양한 언어와 화폐의 영수증을 처리하는 것은 여전히 복잡. 또한 부정확한 분류로 인한 거절과 재제출이 빈번
- 사람들이 실제로 싫어하는 것: "영수증을 올렸는데 분류가 틀렸다고 거절당함", "경비 관리자가 영수증 검토에 1시간 이상 소요", "여러 번 거절되면 결국 체념하고 개인 경비로 처리"

- 시간 비용: 경비 보고서 작성에 월 2~3시간 (직원), 검토에 월 5~10시간 (관리자)

- 소프트웨어 해결 가능성: 높음 (AI 기반 영수증 OCR + 자동 분류)
- AI 해결 가능성: 높음 (다언어 OCR 및 카테고리 자동 분류)
- 1인 개발 가능성: 중간 (OCR 라이브러리 + 회계 시스템 연동)

### 실제 근거

**판정**: 신중채택 — 기존 경쟁사가 있지만, 다언어 OCR 정확도 개선은 아직 과제

## P019. 글로벌 사무직 주간 회의 기록 속기사 필요

- 지역: 전세계
- 국가: 다국가
- 타깃 고객: 회의 진행자, 팀 리더, HR 담당자
- 핵심 문제: 회의가 끝난 후 누군가가 회의 내용을 정리해서 회의록(minutes)을 작성해야 함. 대부분의 경우 회의 참석자 중 한 명이 수동으로 노트를 정리하는데, 이 과정이 시간 소모적. 자동 회의록 도구(Otter.ai, Microsoft Teams 기록 등)가 있지만, 정확도가 완벽하지 않고, 액션 아이템 추출이 미흡

- 시간 비용: 회의록 작성에 주 2~5시간
- 금전 비용: 속기사 고용 경우 월 $500~$2,000
- 문제 심각도 (0~10): 4
- 현재 지출: 무료~월 $200 (자동 기록 도구) 또는 월 $500~$2,000 (속기사)
- 소프트웨어 해결 가능성: 높음 (AI 기반 회의록 자동 작성)
- AI 해결 가능성: 높음 (음성 인식 + 액션 아이템 자동 추출)
- 1인 개발 가능성: 중간 (음성 인식 API 활용)

### 실제 근거
- Otter.ai: "AI 기반 회의 기록" — 정확도 85~95%이지만, 액션 아이템 추출 부정확
- Microsoft Teams: "회의 기록 및 자동 필사" — 팀원들의 추가 검수 필요

③ 기존 SaaS 포함: Yes — Otter.ai, Microsoft Teams, Fireflies.ai 등

## P020. 글로벌 소규모 매장 재고 관리 RFID 미지원

- 지역: 전세계
- 국가: 다국가
- 타깃 고객: 소규모 소매점 주인, 재고 관리자
- 핵심 문제: 소규모 소매점(의류, 화장품, 잡화 등)에서는 여전히 바코드 스캔이나 수작업으로 재고를 관리하고 있음. RFID 기술이 있지만, 도입 비용이 높아서 소규모 매장이 접근하기 어려움. 결과적으로 재고 부정확, 과다 재고, 품절 문제 발생
- 사람들이 실제로 싫어하는 것: "매달 재고 실사에 4~8시간 소요", "시스템과 실제 재고가 맞지 않는 경우 다반사", "고객이 재고 있다고 했는데 찾을 수 없는 경험"
- 현재 해결 방법: 바코드 스캔 (수동 입력), 스프레드시트 관리, RFID 시스템 (도입 매장 소수), 인벤토리 관리 소프트웨어(Shopify, Square 등) 이용
- 발생 빈도: 매월 (재고 실사)
- 시간 비용: 재고 관리에 월 4~8시간
- 금전 비용: 재고 오류로 인한 손실 ($100~$1,000 per month)
- 문제 심각도 (0~10): 5
- 현재 지출: 월 $10~$100 (인벤토리 소프트웨어) 또는 월 $500~$2,000 (RFID)
- 소프트웨어 해결 가능성: 높음 (저가 RFID 솔루션 또는 이미지 기반 재고 인식)
- AI 해결 가능성: 높음 (이미지 인식을 통한 자동 재고 계산)
- 1인 개발 가능성: 중간 (RFID 하드웨어 + 소프트웨어)

### 실제 근거
- Shopify: "소매점 재고 관리" — 바코드 스캔 기반이지만, RFID 미지원
- Square: "인벤토리 관리" — 수동 입력 필요
- 소매점 주인 커뮤니티: "재고 관리 자동화 필요"

### 신호 스크리닝
① 정부 무료 제공: No
② 업계 무료 콘텐츠: No — 각 매장이 자체 관리
③ 기존 SaaS 포함: Partial — Shopify, Square 등이 있지만, RFID 기반 완전 자동화 아님
④ 반복 빈도: 매월

**판정**: 채택 — 소매점의 명확한 pain signal

### 왜 중요한 문제인가
소규모 소매점이 매달 재고 실사에 4~8시간을 낭비하고 재고 오류로 손실 발생. 저가 RFID 또는 이미지 기반 자동 인식이 있으면 시간 절감 및 정확도 향상.

### 가정
- 저가 RFID 솔루션 개발 가능성 확인 필요
- 이미지 인식 기술의 재고 계산 정확도 확인
