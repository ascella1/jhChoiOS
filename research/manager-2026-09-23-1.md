# Idea 001. ClientRadar

## 한 줄 설명

신규 클라이언트와 일하기 전에 그 사람·회사의 잠적/대금지연 이력을 크라우드소싱으로 확인하되, "먼저 1건 제보해야 검색할 수 있다"는 콜드스타트 설계로 서비스 시작일부터 데이터가 쌓이는 프리랜서·컨트랙터용 리스크 레이더.

## 해결하는 Pain

- P013(제안서 작성 후 클라이언트 잠적) — 상대가 어떤 사람인지 미리 알 방법이 없다는 정보 공백
- P017(Net 30/60/90 대금 지급지연) — 계약 전에 이 발주처의 실제 지급 패턴을 알 수 없음
- P019(고객마다 반복되는 COI 요청) — 신뢰를 매번 처음부터 증명해야 하는 구조와 동일한 "상호 신뢰 확인 비용" 문제
- P014(CRM 중복 리드) — "이 상대가 누구인지 정확히 모른 채 일한다"는 동일 계열의 정보비대칭

## 제공하는 Positive Experience

S018(Twitch 구독 배지 — 결제/기여만으로 커뮤니티 내 지위가 채팅에 자동 노출)과 S019(판타지 풋볼 — 참가비를 건 그룹 안에서 서로의 신뢰도를 주간 단위로 확인하는 사회적 게임)를 교차 적용했다. "내가 남긴 제보가 다른 프리랜서의 손실을 막았다"는 실질적 기여감과, 기여 등급 배지가 검색결과·프로필에 자동 노출되는 지위 과시가 핵심이다.

## Target User

Upwork·Fiverr·Freelancer.com 등에서 활동하는 개발자·디자이너·카피라이터, 미국 건설·시설관리 하청 컨트랙터

## 왜 설치하는가

신규 프로젝트 제안을 받은 순간 "이 사람 괜찮을까?"라는 생각이 자연스럽게 들기 때문. Substack·Gumroad에 이미 "잠적 대응" 콘텐츠·상품이 다수 존재한다는 것 자체가 실질적 지불의사를 시사한다.

## 첫 30초

앱 진입 → 클라이언트명/이메일/회사명 검색 → 첫 검색 전 "최근 겪은 클라이언트 경험 1건을 15초 텍스트 또는 음성으로 제보해주세요" 유도 → 제보 즉시 AI가 리스크 태그로 구조화 → 검색 결과 화면에서 기존 제보(있으면) 또는 "데이터 부족 — 공개기록 기반 참고정보"(공개 소액소송·유치권 기록 등 시드 데이터)를 확인.

## 핵심 기능

1. 클라이언트/회사 검색 + 리스크 스코어(데이터량에 따른 신뢰구간 명시, 데이터 부족 시 "저신뢰"로 정직하게 표기)
2. 기여 게이트(제보 1건 → 검색권 획득) + AI 자동 구조화·엔티티 퍼지매칭(오탈자·법인명 변경 대응)
3. 시드 데이터: 공개 BBB·소액소송·유치권(mechanics lien) 기록과 Upwork/Reddit 공개 게시물 요약을 서비스 오픈 전에 AI로 미리 수집해 DB를 비어있지 않은 상태로 시작
4. 기여자 등급 배지(Bronze/Silver/Gold) + "이달의 최다 정확 제보" 랭킹

## 핵심 사용 루프

신규 클라이언트/프로젝트 제안 수신 → 이름·이메일 검색(필요시 자신의 최근 경험 1건 제보) → 리스크 스코어 확인 후 나쁜 계약 회피 또는 안심하고 수락 → 프로젝트 종료 후 실제 결과(제때 지급/지연/잠적)를 재제보해 DB 강화, 배지 레벨업 → 다음 신규 클라이언트 제안 때 재검색

## 반복 사용 이유

프리랜서는 구조적으로 계속 새 클라이언트를 만나므로 "이번 사람은 어떨까"라는 확인 니즈가 반복된다. 제보 없이는 검색권이 제한되므로, 쓸수록 자신의 데이터도 늘어 검색 품질이 좋아지는 선순환이 설계돼 있다.

## Personalization

자신의 업종(개발/디자인/건설)에 맞춘 리스크 항목 가중치, 본인이 자주 겪는 리스크 유형(잠적 vs 지연)을 우선 표시.

## AI 역할

(1) 자유서술 제보를 구조화된 리스크 태그로 변환, (2) 표기 차이(오탈자·법인명 변경)를 감안한 엔티티 퍼지매칭으로 동일인물 식별, (3) 데이터량 대비 신뢰구간을 함께 제시하는 확률적 스코어링(과신 방지), (4) 공개기록 스크레이핑·요약으로 초기 시드 데이터 자동 구축. AI 없이는 자유텍스트 제보를 구조화된 검색가능 DB로 만드는 과정 자체가 성립하지 않는다.

## Sharing

기여 배지가 프로필·검색결과에 자동 노출(별도 공유 행동 불필요, Twitch 배지 구조 차용). 추가로 "이 제보가 도움이 됐다면 동료에게 공유" 버튼으로 레퍼럴 유도.

## Monetization

무료(제보 기반 제한적 검색) + Pro 구독(월 무제한 검색, 월 1.9만원) + 에이전시/스타트업 채용팀 대상 B2B API(월 9.9만원~, 대량 조회)

## MVP

웹앱(Next.js) + Supabase DB + GPT-4o(제보 파싱·엔티티매칭) + 공개기록 스크레이핑 스크립트(BBB·법원 공개기록)로 초기 시드 구축. 특정 서브레딧/Discord 하나의 니치 커뮤니티부터 비공개 베타로 밀도를 확보한 뒤 확장.

## MVP 예상 비용

약 250만원 (LLM API 크레딧 + Supabase + 도메인/호스팅 + 명예훼손 리스크 검토를 위한 소액 법률자문)

## 가장 큰 약점

명예훼손·허위 제보 리스크 — 검증되지 않은 주장이 특정 개인·회사의 실제 평판에 피해를 줄 수 있어, 반박권·이의제기 절차·모더레이션 설계가 필수이며 이 운영 부담이 1인 개발자에게는 상당히 크다.

## 가장 중요한 검증 가설

"제보 1건을 먼저 요구해도 사용자가 이탈하지 않고 제보→검색 루프에 들어오는가" — 니치 커뮤니티 1곳(예: 특정 Upwork 서브카테고리) 100명 베타에서 제보율·검색 재방문율을 확인해야 한다.

# Idea 002. VisitVoice

## 한 줄 설명

일본 부동산 중개 현장직원이 내견(内見) 방문 시 15초 음성으로 도착시간·열쇠 수령 여부·물건 상태를 남기면 AI가 즉시 구조화하고, 열쇠 미수령 등 안내 무산 발생 시 담당 부서에 자동으로 에스컬레이션하는 현장 기록 앱.

## 해결하는 Pain

P009(내견 열쇠 수령 실패로 안내 무산, 중개 담당자 88.3%가 경험). 단, 열쇠 접근 실패 자체(하드웨어 문제)는 소프트웨어로 해결할 수 없다는 점을 정직하게 인정하고, 대신 "실패가 발생했다는 사실과 그 패턴을 즉시 기록·전파"하는 행정 공백을 메운다.

## 제공하는 Positive Experience

S005(스크린골프 — 활동 종료 직후 결과가 즉시 수치화되어 동반자와 비교됨)를 교차 적용. 현장직원의 "이번 주 내견 성공률" 스코어카드가 팀 채팅에 공유되며, 열쇠 문제로 인한 실패가 개인 잘못이 아니라 데이터로 증명되는 구조적 문제라는 것을 회사가 인지하게 된다.

## Target User

일본 임대 부동산 중개회사의 현장 영업직원(内見 안내 담당), 그리고 이들을 관리하는 지점장/본사 담당자

## 왜 설치하는가

"이번에도 열쇠를 못 받았다"는 상황이 반복되는데, 이를 증빙할 방법이 없어 회사가 심각성을 체감하지 못한다는 답답함 때문에. 회사 차원에서는 스마트키 전환 우선순위를 정할 데이터가 필요해서 도입.

## 첫 30초

현장 도착 → 앱 열고 마이크 버튼 → "OO맨션 302호, 10시 15분 도착, 열쇠박스 코드 오류로 미입실, 고객 대기 중" 15초 발화 → 즉시 구조화된 방문 로그 카드 생성, 미입실 항목은 자동으로 담당자에게 알림 전송.

## 핵심 기능

1. 방문 시 15초 음성 로그 → AI 자동 파싱(주소·시각·열쇠수령 성공/실패·물건상태 메모)
2. 실패 발생 즉시 담당 부서/스마트키 관리자에게 자동 에스컬레이션 알림
3. 물건별·직원별 "내견 성공률" 대시보드, 반복 실패 물건 자동 하이라이트(스마트키 전환 우선순위 근거자료)

## 핵심 사용 루프

내견 방문 도착 → 15초 음성으로 결과 기록 → 실패 시 즉시 에스컬레이션·성공 시 자동 완료 처리 → 주간 팀 스코어카드로 성공률 공유 → 반복 실패 물건 데이터가 쌓여 회사의 스마트키 전환 의사결정 근거가 됨 → 다음 내견 방문 시 재사용

## 반복 사용 이유

내견 방문은 하루 여러 건 발생하는 고빈도 업무이며, 기록을 남기지 않으면 본사가 문제의 심각성을 알 수 없어 직원 스스로도 방어 기록으로서 남기고 싶어진다.

## Personalization

담당 지역·자주 다루는 물건 유형별 자주 쓰는 메모 템플릿 자동 학습.

## AI 역할

음성을 구조화된 방문 로그로 변환하고, 실패 유형(열쇠박스 오류/열쇠 자체 부재/고객 노쇼 등)을 자동 분류해 에스컬레이션 대상을 정확히 라우팅한다. AI 없이는 자유발화를 실시간 구조화된 알림으로 바꾸는 것이 불가능하다.

## Sharing

개인 간 공유보다는 팀/지점 단위 주간 스코어카드 공유가 핵심이며, 별도의 SNS성 공유 유인은 설계하지 않았다(B2B 도구 특성상 정직하게 낮게 평가).

## Monetization

부동산 중개회사 대상 B2B SaaS, 직원 좌석당 월 구독(1인당 월 3,000엔 수준) + 스마트키 벤더 제휴 리퍼럴 수수료

## MVP

OpenAI Whisper(일본어) + GPT-4o 파싱 + Supabase 백엔드 + 카카오톡 대신 LINE WORKS 알림 연동. 중개회사 1곳과 파일럿.

## MVP 예상 비용

약 200만원 (음성 API 크레딧 + 백엔드 호스팅 + LINE WORKS API 연동 개발)

## 가장 큰 약점

개별 직원이 아니라 회사 단위로 도입돼야 가치가 커지는 구조라, 1인 사용자에게는 매력이 약하고 B2B 영업(회사 단위 채택)이 필요해 1인 개발자에게 판매 난이도가 높다.

## 가장 중요한 검증 가설

"현장직원이 방문마다 실제로 15초 음성 기록을 빠짐없이 남기는가, 아니면 바쁠 때 생략하게 되는가" — 실제 현장 1개 지점 2주 파일럿에서 기록 누락률을 확인해야 한다.

# Idea 003. PayClear

## 한 줄 설명

PT 트레이너가 회원 결제 알림(카카오페이·토스)을 캡처해 올리면 AI가 수수료·세금 차감분을 자동 계산해 "이번 달 진짜 실수령액"을 실시간으로 보여주는 정산 투명화 대시보드.

## 해결하는 Pain

P001(헬스장 수수료 정산 불투명, 실수령액이 결제액의 절반 이하로 떨어져도 검증 수단이 없음)

## 제공하는 Positive Experience

S002(바디프로필 — 수개월간의 노력이 숫자·시각자료로 증명되는 경험)를 교차 적용. 트레이너의 노력(수업 소진)이 "얼마를 벌었는가"라는 명확한 숫자로 매달 증명되고, 이 리포트가 협상·이직 시 근거자료가 된다.

## Target User

헬스장 소속 계약직/프리랜서 개인 PT 트레이너

## 왜 설치하는가

"얼마 받는지도 모르고 일한다"는 답답함을 해소하고 싶어서. 헬스장 정산 시스템에 의존하지 않는 자기 자신만의 검증 기록이 필요해서.

## 첫 30초

결제 알림 캡처 3~5장 업로드 → AI가 회원별 결제 항목 자동 인식 → "이번 달 결제액 대비 예상 실수령액" 첫 추정치 확인.

## 핵심 기능

1. 결제 알림 캡처 OCR + 회원별 정산 내역 자동 집계
2. 수수료율·세금 차감 반영한 "실수령 예상액" 실시간 계산
3. 사물함·운동복 대여료 등 부가비용 누락 항목 자동 하이라이트
4. 월간 "내 진짜 수입 리포트" 카드 생성(공유 가능한 시각 자료)

## 핵심 사용 루프

세션 완료 → 결제 알림 캡처 업로드 → 회원별 정산 자동 집계 확인 → 월말 실수령 리포트 확인 → 다음 달 협상/이직 판단 자료로 축적 → 다음 세션 결제 시 재사용

## 반복 사용 이유

매 세션 결제가 발생할 때마다 기록해야 정확한 월간 집계가 나오므로, 정산의 정확성을 원하는 트레이너일수록 세션 단위로 습관화된다.

## Personalization

소속 헬스장의 수수료 구조(고정률/구간별)를 개인별로 학습해 적용.

## AI 역할

결제 알림 캡처의 OCR 인식과 항목 분류, 그리고 회원별 소진 이력과 대조해 "정산 누락 의심 항목"을 자동 하이라이트하는 이상탐지. 단순 계산기 수준을 넘어서는 부분은 이 이상탐지와 부가비용 항목 자동 인식이다.

## Sharing

월간 수입 리포트 카드를 트레이너 커뮤니티(오픈채팅방 등)에 "이번 달 내 진짜 수령액" 형태로 공유해 동료 간 수수료 구조 비교·정보 공유 유도.

## Monetization

개인 트레이너 대상 월 4,900원 소액 구독(정산 추적+월간 리포트)

## MVP

OCR(Google Vision API) + GPT-4o 항목분류 + Supabase. 개인 기록용 MVP는 헬스장 POS 연동 없이도 가능.

## MVP 예상 비용

약 150만원

## 가장 큰 약점

헬스장 POS/CRM과 직접 연동하지 못해 트레이너가 결제 캡처를 매번 수동 업로드해야 하는 입력 부담이 남아있고, 이는 장기 사용률을 떨어뜨릴 수 있다.

## 가장 중요한 검증 가설

"결제 캡처 업로드라는 수동 입력을 트레이너가 실제로 매 세션 지속하는가" — 2주 파일럿에서 업로드 누락률을 확인해야 한다.

# Idea 004. PetLaunch Kit

## 한 줄 설명

펫호텔·애견유치원 창업 예정자가 소재지를 입력하면 해당 지자체의 동물위탁관리업 등록 요건 체크리스트와 신청서류 초안을 AI가 자동 생성해주는 창업 준비 도구.

## 해결하는 Pain

P002(동물위탁관리업 등록·시설기준 규제 부담, 지자체별 기준 불일치로 인한 예측 불가능성)

## 제공하는 Positive Experience

S006(클래스101 — 무제한 구독으로 "일단 가볍게 시도해보자"는 진입장벽 제거)을 교차 적용. 창업이라는 큰 결정 앞에서 "일단 내 지역 요건이 뭔지부터 가볍게 확인해보자"는 부담 없는 첫걸음을 제공.

## Target User

펫호텔·애견유치원·펫시터 서비스 창업을 준비하는 1인·소규모 창업자

## 왜 설치하는가

행정사에게 맡기기엔 이르고, 혼자 법령을 읽기엔 막막한 단계에서 "내 지역 기준이 뭔지"부터 빠르게 알고 싶어서.

## 첫 30초

주소(시·군·구) 입력 → 해당 지자체의 시설기준 체크리스트 즉시 표시 → "지금 충족 못하는 항목" 하이라이트.

## 핵심 기능

1. 지자체별 시설기준·서류요건 체크리스트 자동 생성
2. 사업계획서·시설 배치도 초안 AI 생성
3. 온라인 교육 이수 등 필수 절차 안내 및 진행상황 체크

## 핵심 사용 루프

지역 입력 → 체크리스트 확인 → 미충족 항목 파악 → 서류 초안 생성 → (실사 대응 후) 등록 완료 → 갱신 시점에 재방문

## 반복 사용 이유

창업 준비 단계에서 여러 번 체크리스트를 재확인하지만, 등록 완료 후에는 자연빈도가 거의 사라지는 구조적 약점이 있다.

## Personalization

지자체별 규정 차이를 반영한 맞춤 체크리스트.

## AI 역할

지자체별로 흩어진 조례·시행규칙 텍스트를 파싱해 구조화된 체크리스트로 변환하고, 사용자 상황에 맞는 사업계획서 초안을 생성.

## Sharing

낮음 — 창업 준비는 개인적 과정이라 공유 유인이 약하다.

## Monetization

체크리스트+서류초안 1회 이용권(건당 2.9만원), 행정사 매칭 리퍼럴 수수료

## MVP

지자체 조례 데이터 수집(공공데이터포털) + GPT-4o 문서생성 + 간단한 웹 체크리스트 UI

## MVP 예상 비용

약 120만원

## 가장 큰 약점

사용 빈도가 창업 준비 기간에 국한된 1회성에 가까워 Retention이 구조적으로 매우 낮다. 실사 통과 여부까지 보장하지 못해 신뢰 구축도 쉽지 않다.

## 가장 중요한 검증 가설

"체크리스트만으로 행정사 대행 없이 실제 등록까지 완료하는 사용자가 존재하는가" — 존재하지 않는다면 이 제품은 행정사행 리드 생성 도구로 재정의되어야 한다.

# Idea 005. MarginPulse

## 한 줄 설명

일본 음식점 오너가 식자재 원가를 입력하면 AI가 최적 판매가·마진율을 시뮬레이션하고, 익명화된 동종업계 인상률 벤치마크와 비교해주는 가격결정 도구.

## 해결하는 Pain

P012(식자재 원가상승 대응, "가격을 올리면 손님이 안 올 것"이라는 불안으로 인한 가격 결정 마비)

## 제공하는 Positive Experience

S005(스크린골프 — 활동 직후 결과를 즉시 수치화해 동반자와 비교)를 교차 적용. 자신의 가격 인상 계획을 익명 벤치마크와 즉시 비교해 "나만 무리하게 올리는 게 아니다"라는 안도감을 준다.

## Target User

개인·소규모 음식점 오너(일본)

## 왜 설치하는가

가격 인상이 두렵지만 원가 상승은 실재하는 상황에서, 감이 아닌 숫자와 동종업계 비교 데이터로 결정하고 싶어서.

## 첫 30초

# 가장 중요한 관찰

**1. 오늘 신호 세트는 전반적으로 "니치 B2B·전문직 정보비대칭" 성격이 강해 Retention이 구조적으로 낮은 아이디어가 많았다.** 12개 중 절반 이상이 사용 트리거가 비정기적 사건(결근, 독립, 청구 반려)이거나 1회성 생애 이벤트(창업 등록, 독립 개업)에 가까워, 자연빈도 자체가 낮다는 한계를 점수에 정직하게 반영했다. S등급이 하나도 없고 A가 1개뿐인 것은 점수를 억지로 높이지 않은 결과다.

**2. CEO 지시 이행: 콜드스타트를 실제로 설계에 내장한 크라우드소싱 메커니즘 — ClientRadar.** TrustScore·GachaCert(09-22-2)가 "콜드스타트 미해결"로 Market Agent에게 드롭 권고를 받았던 것과 달리, 이번 ClientRadar는 (1) 공개기록(BBB·소액소송·유치권 기록) 사전 스크레이핑으로 시드 데이터를 확보하고, (2) "제보해야 검색 가능"이라는 give-one-get-one 구조로 사용과 데이터 성장을 강제 결합하며, (3) 단일 니치 커뮤니티부터 밀도를 확보하는 롤아웃 전략을 명시했다. 이는 시장성 평가가 아니라 "메커니즘 자체의 설계 완결성" 문제이므로 Manager 단계에서 다뤘다.

**3. "음성 15초 패턴"은 이번에는 억지로 새 도메인에 끼워 넣지 않았다.** CEO가 지정한 간호사 병동기록·현장기술자 점검기록은 오늘 40개 신호 어디에도 정확히 대응하는 신호가 없었다. 대신 구조적으로 가장 근접한 P009(일본 부동산 현장직원의 물리적 현장 방문·즉시 기록 필요성)에 이 패턴을 적용했다(VisitVoice). 다음 회차에 negative-agent가 의료·현장점검 영역의 신호를 실제로 발굴한다면 그때 정확히 지정된 도메인에 적용할 것을 권장한다.

**4. 프리랜서/컨트랙터 신뢰·현금흐름 클러스터(P013,P014,P017,P019)가 오늘 가장 강한 Pain 밀도를 보였다.** ClientRadar 하나로 이 클러스터의 다수 신호를 통합 해결하는 접근이, 신호별로 개별 도구를 만드는 것보다 제품 구조상 더 타당하다고 판단해 하나의 아이디어로 집중시켰다.
