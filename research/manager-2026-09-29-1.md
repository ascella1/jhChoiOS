# Idea 001. 월세 네비게이터 - RentAlign

## 한 줄 설명
월세 상승과 전세 부족 시대에 AI가 인근 월세 데이터를 실시간 추적하고 협상 가이드를 제공하는 임차인 맞춤 서비스.

## 해결하는 Pain
P001 (월세 상승), P001 (전월세 부담 증가)

## 제공하는 Positive Experience
S003, S012 (매일 확인하는 구독 경험), S019 (자동 추적)

## Target User
서울·수도권 20~35세 청년 임차인, 월세 갱신 예정자, 방 구하는 중인 직장인

## 왜 설치하는가
"내 방 월세가 올랐는데, 근처 시세는 얼마일까?"를 한 번의 탭으로 확인하고 싶음. 협상 근거가 필요함.

## 첫 30초
주소 입력 → 인근 월세 평균값, 상승률, "현재 시세 대비 당신은 500만원 더 내고 있음" 메시지 노출

## 핵심 기능
1. 실시간 월세 시세 추적 (공시데이터 + 부동산 API)
2. 개인 월세 기록 → 자동 비교
3. 협상 템플릿 및 가이드
4. 예상 월세 상승률 (30일, 90일 전망)
5. 건물주 연락처 없이 협상 드래프트 생성

## 핵심 사용 루프
월세 올렸나 확인(Trigger) → 앱 열기 → 인근 시세 비교 → "이 정보로 협상하자"(Action) → 협상 성공 가능성 보기(Reward) → 다음 달 다시 확인(Investment → Next Trigger)

## 반복 사용 이유
월세는 월마다 갱신 논의가 있으므로, 매월 초 또는 계약 3개월 전에 반복적으로 확인 필요. 또한 시장이 변할 때마다 (금리 인상, 부동산 뉴스) 알림이 오므로 중독성 높음.

## Personalization
개인 거주 지역 × 건물 유형 × 계약 잔여 기간 → 맞춤 협상 시점 알림
선호 이사 시기, 최대 부담금 설정 → 매칭되는 방 추천

## AI 역할
필수. 주가 데이터, 금리, 부동산 뉴스, 거주 지역 정보를 학습해 "당신은 X개월 후 월세 인상이 올 가능성 80%"라는 예측 제공.

## Sharing
"근처 월세가 이렇게 올랐어?"라며 친구에게 공유. 이사를 함께 고려하는 친구들과 협력.

## Monetization
- Freemium: 기본 월세 시세 조회는 무료
- Premium (월 4,900원): 협상 템플릿, 30/90일 전망, 전문가 상담 1회/월
- B2B (건물주/공인중개사): 월세 시장 리포트 판매

## MVP
1. 서울/강남/강북 지역 월세 시세 공시데이터 수집
2. 사용자 주소 입력 후 인근 200m 월세 평균값 표시
3. 개인 월세 기록 입력 → 시세 대비 비교
4. 협상 템플릿 5가지 (기본, 보증금 증액 교환, 급 갱신료 요청 등)

## MVP 예상 비용
- 데이터 수집/정제: 150만원
- 백엔드 서버: 50만원
- 프론트엔드 (iOS/Web): 150만원
- AI 모델 (공개 API 활용): 30만원
- 초기 배포 및 QA: 50만원
**합계: 430만원** (300만원 이내를 위해 웹 먼저, 데이터 파트너십 활용)

## 가장 큰 약점
1. 공시데이터는 지연이 있어 실시간 부정확
2. 지역이 작아지면 샘플 부족
3. 협상 성공 여부를 측정하기 어려움

## 가장 중요한 검증 가설
"사용자가 실제로 협상에 성공했는가?"를 측정하는 것이 핵심. 또한 월세는 한 번 정해지면 12개월이므로, 반복 사용율이 낮을 수 있음 → "다음 갱신 시점"을 알림으로 자극하는 설계 필수.

# Idea 002. 배달앱 수수료 네비게이터 - DeliveryCheck

## 한 줄 설명
배달앱들이 숨긴 "실제 수수료 구조"를 투명하게 비교하고, 가장 싼 앱으로 자동 안내하는 음식 배달 의사결정 도구.

## 해결하는 Pain
P002 (배달앱 숨겨진 수수료 구조)

## 제공하는 Positive Experience
S005 (게임화된 경험 - 절약 포인트), S019 (자동 추적)

## Target User
주 3회 이상 배달 앱을 사용하는 직장인, 자취생, 음식점 사업주

## 왜 설치하는가
"배달료 0원"이라는 표시 뒤에 숨겨진 음식값 인상(수수료 전가)을 알고 싶음. 어느 앱이 가장 저렴한지 한눈에 보고 싶음.

## 첫 30초
음식점 검색 → "배달의민족: 15,000원 (수수료 36% 포함)", "쿠팡이츠: 14,000원 (수수료 15%)" 비교표 노출. 가장 싼 앱 추천.

## 핵심 기능
1. 주요 배달앱 (배민, 쿠팡, 요기, 배달통) 동시 검색
2. 음식점별 수수료율 + 최종 가격 계산
3. 절약액 자동 계산 ("이 주문으로 2,000원 절약!")
4. 월 누적 절약액 대시보드

## 핵심 사용 루프
점심 주문(Trigger) → 앱 검색 → 가장 싼 앱 선택(Action) → 절약액 보기(Reward) → 내일도 확인(Investment)

## 반복 사용 이유
매일 또는 주 3회 이상 배달 앱 사용. 매번 "어디서 시킬까"를 고민할 때마다 앱을 열 동기가 있음.

## Personalization
개인이 자주 가는 음식 카테고리 → 그 카테고리에서 가장 싼 앱 추천
위치 기반 → 해당 지역의 배달 가능 음식점만 표시

## AI 역할
음식점별 수수료율 예측 (일부 숨겨진 수수료), 배달시간 + 가격을 조합한 최적 선택 추천

## Sharing
"오늘 배달비 2,000원 절약했어" 스냅샷 친구에게 공유

## Monetization
- Freemium: 기본 비교는 무료
- Premium (월 2,900원): 음식점별 상세 수수료 분석, 월 절약액 리포트, 최적 주문 시간 추천
- B2B: 음식점 사업주에게 "자신의 수수료율" 투명 공개 리포트 판매

## MVP
1. 배달의민족 + 쿠팡이츠 크롤링 (또는 API 파트너십)
2. 사용자가 음식 검색 → 앱별 가격 + 수수료율 비교표
3. 절약액 자동 계산 표시
4. 가장 싼 앱 바로 링크

## MVP 예상 비용
- 데이터 크롤링 (Selenium 자동화): 100만원
- 백엔드 서버 (음식점 인덱싱): 80만원
- 프론트엔드 (모바일 웹): 120만원
- 초기 배포: 30만원
**합계: 330만원** (웹 먼저, API 파트너십으로 크롤링 최소화)

## 가장 큰 약점
1. 배달앱들이 수수료 공개를 꺼릴 수 있음 (크롤링 차단)
2. 실시간 가격 변동이 빨라 정확도 유지 어려움
3. 배달앱의 약관상 "가격 비교 서비스" 허용 여부 불명확

## 가장 중요한 검증 가설
"배달앱들이 크롤링을 허용할 것인가?" vs "직접 API 파트너십을 맺을 수 있을 것인가?"를 먼저 검증해야 함. 또한 사용자가 실제로 "더 싼 앱"으로 주문을 변경하는지 추적 필수.

# Idea 003. DevSecCheck - 개발자 AI 코드 검증 도우미

## 한 줄 설명
ChatGPT나 Claude가 생성한 코드의 "거의 맞지만 틀린 버그"를 자동으로 찾고, 개발자의 검증 시간을 50% 줄이는 GitHub PR 자동 검토 봇.

## 해결하는 Pain
P013 (AI 생성 코드 검증 시간 과다 소비 - 주 11.4시간)

## 제공하는 Positive Experience
S013 (AI를 활용한 자동화), S006 (자동 공유)

## Target User
AI 코드 생성을 자주 사용하는 소프트웨어 개발자, 초기 스타트업 개발팀 (1~5명)

## 왜 설치하는가
AI 코드를 100% 신뢰할 수 없지만, 수동으로 일일이 검토하기에는 시간이 너무 오래 걸림. 자동으로 "주의할 부분"을 지적받고 싶음.

## 첫 30초
GitHub PR 생성 → DevSecCheck가 자동으로 PR 분석 → "이 함수는 null 체크 누락, 이 API 호출은 timeout 없음" 등 주의점 코멘트 1분 내 작성

## 핵심 기능
1. GitHub PR 자동 감시
2. AI 생성 코드 패턴 인식 (ChatGPT, Claude 구별)
3. 일반적인 버그 패턴 자동 탐지 (null pointer, timeout, injection, 성능)
4. "AI 코드에서 자주 발생하는 오류 10가지" 리스트로 검증
5. 위험도별 자동 코멘트

## 핵심 사용 루프
개발자 AI 코드 작성(Trigger) → PR 생성 → DevSecCheck 자동 실행(Action) → 주의점 리스트 받음(Reward) → 다음 PR도 자동 확인(Investment)

## 반복 사용 이유
매일 또는 주 5회 이상 PR을 생성하는 개발자에게, 매번 자동으로 검증이 들어오므로 "이 코드 괜찮은가?" 불안감 해소

## Personalization
팀별 코드 스타일 × 프로젝트 언어 → AI 검증 규칙 커스터마이징
개발자 경력 수준 → 상세도 조정

## AI 역할
필수. 1) AI 생성 코드 패턴 인식, 2) 정적 분석 (잘 알려진 도구)와 다르게 AI 특화 오류 학습, 3) PR 텍스트에서 "이건 AI가 생성했나?"를 자동 감지

## Sharing
PR 리뷰어에게 "DevSecCheck가 이미 검증했으니 빠르게 승인" 신호. 팀 내 "AI 코드 검증 강화" 문화 형성

## Monetization
- Freemium: PR당 3개 코멘트까지만 (대부분 팀이 더 많으므로 유료로 전환)
- Team Pro (월 29,900원/팀): 무제한 PR 검증, 팀 커스텀 규칙, 주간 리포트
- Enterprise: 자체 서버 배포, SLA 보장

## MVP
1. GitHub App 등록 (권한: PR 읽기, 코멘트 작성)
2. PR이 생성되면 diff 받아서 분석
3. Claude API로 "이 코드에서 일반적 버그 5가지"만 찾기
4. 주요 언어 (Python, JS, Java)만 먼저 지원

## MVP 예상 비용
- GitHub App 개발: 100만원
- Claude API 통합: 50만원
- 백엔드 서버 (이벤트 처리): 80만원
- 초기 배포 + 문서: 50만원
**합계: 280만원** (충분히 300만원 이내)

## 가장 큰 약점
1. "AI 코드"와 "일반 코드"를 구별하기 어려운 경우 많음
2. 오탐(false positive)이 많으면 팀에서 무시할 가능성
3. 기존 정적 분석 도구 (SonarQube, ESLint)와의 경쟁

## 가장 중요한 검증 가설
1. "정말 AI 코드에서만 발생하는 버그 패턴이 있는가?" 검증
2. "개발팀이 실제로 검증에 시간을 절약했는가?" 추적 (리뷰 시간 단축)
3. "오탐율이 5% 이하여야 팀에서 신뢰한다"는 기준 설정

## 한 줄 설명
AWS 청구 오류로 인한 공포감을 없애고, 일일 비용을 투명하게 추적하며, 30/90일 청구액을 AI로 미리 예측하는 클라우드 CFO 어시스턴트.

## 해결하는 Pain

## 제공하는 Positive Experience
S019 (개인 포트폴리오 자동 추적), S016 (일일 스트릭 모니터링)

## Target User
AWS를 사용하는 스타트업 개발자, CTO, 팀장 (월 청구액 100만원 이상)

## 왜 설치하는가

3. 30/90일 청구액 AI 예측 (시계열 분석)
4. "비용 증가 원인" 자동 분석 (어느 서비스? 왜?)
5. "이 비용은 어제보다 XXX 올랐습니다" 알림
6. 비용 절감 제안 (예: "Reserved Instance 사면 30% 절약")

## 핵심 사용 루프

## Personalization

필수. 1) 시계열 예측 (ARIMA, Prophet), 2) 비용 이상 감지, 3) 비용 절감 기회 제안 (Savings Plans, Reserved Instances)

# Idea 005. SubscriptionX - SaaS 비용 자동 감시 & 절감

## 해결하는 Pain
P016 (SaaS 구독료 누적으로 인한 비용 폭등)

## 제공하는 Positive Experience

직원 10명 이상의 스타트업/중소기업, CTO, CFO, HR 매니저

"우리 팀이 지금 몇 개의 SaaS를 쓰고 있을까?" 정확히 모름. 매달 자동 갱신되므로 누적 비용이 폭증. 중복이나 미사용 구독을 찾고 싶음.

4. "중복 구독" 탐지 (같은 기능의 다른 도구)
5. 구독별 "사용자 수 대비 가격" 분석

매월 청구(Trigger) → SubscriptionX 분석(Action) → "월 $450 절감 가능"이라는 리포트(Reward) → 미사용 구독 취소(Investment)

필수. 1) 청구 항목에서 SaaS를 자동으로 분류, 2) 사용 데이터에서 "미사용" 판정, 3) "유사한 경쟁 도구" 제안 (예: Figma 쓰는데 Adobe도 있으면 지적)

# Idea 006. SafeTrade - 중고거래 검증 & 보안 플랫폼

## 한 줄 설명
중고거래 사기(피싱, 가짜 결제 링크)를 자동으로 감지하고, 모든 거래를 블록체인 기반 에스크로우로 보호하며, 거래 기록을 자동으로 저장하는 신뢰할 수 있는 중고 마켓플레이스.

## 해결하는 Pain
P005 (중고거래 사기, 정산 지연 - 피해 8,740억원, 사기 10배 증가)

## 제공하는 Positive Experience
S006 (자동 공유 및 기록), S019 (자동 추적)

## Target User
중고나라/당근마켓 활성 사용자 (월 5회 이상), 고가 물품 판매자, 구매자

## 왜 설치하는가
"안전 결제"라고 했는데 피싱 링크였다. 가짜 은행 페이지로 유도되었다. 정산 후 6개월이 지났는데 돈이 안 나온다. 증거가 필요한데 거래 기록이 날아갔다.

## 첫 30초
중고거래 링크 붙여넣기 → SafeTrade가 자동으로 분석 → "판매자 신뢰도 95%, 거래 보호됨 ✓" 표시. 또는 "주의: 피싱 링크 감지" 경고.

## 핵심 기능
1. 거래 상대방 신뢰도 점수 (거래 이력, 리뷰, 사기 신고 등)
2. 거래 링크 안전성 검사 (피싱 탐지)
3. 에스크로우 보호 (돈을 중간에 보관했다가 거래 완료 후 지급)
4. 모든 거래 자동 기록 (증거 저장)
5. 거래 중 분쟁 시 중재 (채팅 기록, 사진 기반)
6. 신고 시스템 (사기꾼 적발 및 신고)

## 핵심 사용 루프
중고거래 시작(Trigger) → SafeTrade로 거래 등록(Action) → 에스크로우 보호 확인(Reward) → 거래 완료 후 자동 기록 저장(Investment)

## 반복 사용 이유
중고거래를 자주 하는 사람은 "매번" SafeTrade를 통해 거래. 또한 거래 기록이 누적되므로 신뢰도가 높아짐 → 다음 거래도 신뢰도 높은 상대와만 거래 가능.

## Personalization
개인의 거래 이력 → 신뢰도 점수 (거래 많을수록, 완료율 높을수록 높음)
물품 카테고리별 사기 위험도 상이 → "고가 전자제품은 특히 주의" 경고

## AI 역할
필수. 1) 거래 상대방 신뢰도 점수 (거래 이력, 리뷰, 사기 신고 등 학습), 2) 피싱 링크 자동 감지 (URL 패턴, 도메인 검사), 3) 거래 중 "위험한 신호" 감지 (예: 갑자기 은행 이체 요청, 빠른 결제 압박)

## Sharing
신뢰도 높은 판매자 프로필을 친구에게 추천. "이 사람과는 안전하게 거래할 수 있어"라는 평판 공유.

## Monetization
- Freemium: 기본 거래 기록, 신뢰도 조회 무료
- Seller Pro (월 4,900원): 프로필 강화, 구매자 신뢰도 배지, 자동 응답 템플릿
- Buyer Protection (월 9,900원): 자동 에스크로우, 분쟁 중재, 환불 보증
- Transaction Fee (거래액 2%): 에스크로우 사용 시 수수료 (기존 배열과 유사하게)

## MVP
1. 중고거래 링크 입력 → 상대방 정보 불러오기
2. 신뢰도 점수 계산 (거래 이력 기반, 초기는 하드코딩)
3. 피싱 링크 검사 (VirusTotal API, URL 패턴)
4. 거래 기록 저장 (사진, 채팅, 결제 스크린샷)
5. 분쟁 신고 폼

## MVP 예상 비용
- 백엔드 (거래 기록, 신뢰도 계산): 120만원
- 프론트엔드 (안드로이드/iOS): 150만원
- VirusTotal API 통합: 30만원
- 초기 배포, 문서화: 50만원
**합계: 350만원** (웹 먼저, 하이브리드 앱 우선)

## 가장 큰 약점
1. 기존 중고나라/당근마켓 생태계에 이미 신뢰도 시스템 있음
2. 에스크로우 서비스는 금융 규제 필요 (복잡함)
3. 피싱 탐지의 오탐/미탐 가능성 높음

## 가장 중요한 검증 가설
1. "사용자가 실제로 더 안전하다고 느끼는가?"를 NPS로 측정
2. "에스크로우를 통해 분쟁이 줄어들었는가?"를 추적

# Idea 007. BurnoutAlert - 직장인 번아웃 예측 & 회복 앱

## 한 줄 설명
직장인의 일일 스트레스, 수면, 감정을 추적하고 AI가 "번아웃 예측"을 3주 전 경고하며, 회복 프로그램을 자동 제안하는 멘탈 헬스 어시스턴트.

## 해결하는 Pain
P006 (직장인 과로 야근으로 인한 번아웃 증후군 - 85% 경험)

## 제공하는 Positive Experience
S016 (일일 체크인 스트릭), S003 (매일 확인하는 구독)

## Target User
20~40대 직장인, 특히 야근이 잦은 IT/스타트업 직원, 팀장

## 왜 설치하는가
"나 번아웃되는 건 아닐까?"라는 불안감. 손실감, 무기력감, 수면 부족이 있지만 병원 가기 전에 스스로 체크하고 싶음. 조기에 대응하고 싶음.

## 첫 30초
아침에 열기 → "오늘 기분 선택 (😊 / 😐 / 😞)" 한 번의 탭 + "수면 시간 입력" → 자동으로 "번아웃 위험도: 3/10" 표시

## 핵심 기능
1. 일일 감정 체크인 (30초)
2. 수면 시간 자동 추적 (웨어러블/폰 센서)
3. 번아웃 위험도 점수 (PHQ-9, 정신 건강 진단)

# Idea 012. SecurityStreak - 계정 보안 일일 체크인 & 보안 점수

## 한 줄 설명

## 해결하는 Pain
P018 (구글 계정 해킹, 2단계 인증 우회), P019 (Windows 강제 업데이트)

S016 (일일 스트릭), S003 (매일 확인하는 구독)

온라인 보안을 신경 쓰는 개인, 30~60대, 특히 중요 계정 많은 사람 (은행, 이메일, SNS)

## 왜 설치하는가
"내 계정들이 안전한가?" "해킹됐는지는 어떻게 확인하지?" "모든 계정마다 강한 비밀번호로 바꿔야 하나?" 불안감.

5. 보안 점수 주간/월간 리포트

## 핵심 사용 루프
아침 루틴(Trigger) → SecurityStreak 열기 → 일일 보안 점수 확인(Action) → 스트릭 유지(Reward) → 다음날도 확인(Investment)

# 가장 중요한 관찰

## 제품 기회의 공통점

### 1. **자동화가 핵심** (7/13개 제품)
Pain(번거로움, 시간 낭비)을 "자동 감지 + 자동 대응"으로 해결.
예: AWS 청구액 자동 추적, SaaS 미사용 자동 탐지, WiFi 자동 VPN, 코드 자동 검증

### 2. **매일/주마다 반복 사용**이 필수
"월 1회" 같은 낮은 빈도는 낮은 점수. 모든 높은 점수 제품은 "주 1회 이상" 또는 "매일"
예: 배달앱 (매일), 월세 (월 초), 번아웃 (매일)

### 3. **개인화 × 사용자 추적**
단순 정보 제공만으로는 낮음. 개인의 "거래 기록", "선호", "패턴"을 학습해서 다음 행동을 예측.
예: S019 (포트폴리오 자동 추적) 같은 Positive가 Negative Pain과 결합하면 강함.

### 4. **첫 사용 가치가 명확해야 함**
"첫 30초에 뭘 얻는가?"가 중요. 모호한 제품은 설치 후 이탈.
예: 월세는 "근처 월세 평균값" → 즉시 가치. 의료비는 "뭔가 복잡한 계산" → 이탈.

### 5. **AI 활용 여부가 Grade를 구분**
AI가 없으면 B 이하. 하지만 AI 활용이 "필수"가 아닌 "선택"일 때도 있음.
예: DeliveryCheck는 AI 필수 아님 (단순 수수료 비교), 하지만 DevSecCheck는 필수.

### 6. **포트폴리오 다양성 확보**
- 소비자 고빈도 (I001, I002, I005, I006, I007): 월세, 배달, SaaS, 중고거래, 번아웃
- B2B (I003, I004, I011): 개발자, 클라우드, DevOps
- 니치 (I008, I009, I010): 애니 팬, 관광객, 보안)
- 전문직 B2B 정보 비대칭은 제한적 포함
