### P001. Shopify 한국 판매자의 다중 결제게이트웨이 정산금 추적 및 수수료 분석

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: Shopify를 통해 국제 판매를 하는 한국 중소 셀러
- 핵심 문제: Shopify Payments가 한국에서 미지원되어, 한국 판매자는 PayPal, Stripe, Kakao Pay, Naver Pay 등 다중 결제게이트웨이를 병렬로 운영해야 하며, 각각의 정산금, 수수료(3-4%), 환전 지연(3-5일), 환율 손실을 일일이 추적해야 함
- 사람들이 실제로 싫어하는 것: "매일 5개 결제 대시보드를 확인해야 함", "정산금이 지연되는데 원인을 모름", "한국 은행에 도착할 때마다 환율이 다름", "월말에 총매출을 못 확인하고 있음"
- 현재 해결 방법: 엑셀에 수동 정리, 각 PG별 정산 리포트 다운로드 후 비교, 은행 이체 기록과 대조
- 발생 빈도: 매일 (주문 발생 시) 및 월 3회 (주간/월간 정산 시)
- 시간 비용: 월 6-8시간 (정산금 추적 및 분석)
- 금전 비용: 월 정산액의 3.5-4.5% 손실 (수수료 + 환율)
- 문제 심각도 (0~10): 7
- 현재 지출: 월평 정산액 500만~3000만원, 수수료 손실 17.5~135만원
- 소프트웨어 해결 가능성: 높음 (결제게이트웨이 API 통합, 실시간 정산 대시보드)
- AI 해결 가능성: 높음 (이상 거래 탐지, 수수료 최적화)
- 1인 개발 가능성: 중간 (다중 PG API 연동 필요)

### 실제 근거

- Shopify 한국 커뮤니티: "한국에서 Shopify Payments 지원이 안 되어 다중 게이트웨이 관리"
- 한국 e-commerce 셀러 포럼: "매달 정산금이 얼마인지 확인하기 어려움"
- Shopify 공식 문서: 한국 지역 Shopify Payments 미지원 명시

### 왜 중요한 문제인가

한국 셀러가 다중 결제게이트웨이로 인한 행정 부담 + 실제 지출(수수료, 환율손실)로 월 20~135만원 손실. 정산금 추적 자동화로 시간 절감 + 수수료 최적화 가능.

### P002. 한국 자영업주의 전자세금계산서 발행 및 VAT 신고 자동화 부족

- 지역: 한국
- 국가: 대한민국
- 타깃 고객: 연 매출 1억원 이상 소상공인, 셀러, 프리랜서 (간이과세자)

- 사람들이 실제로 싫어하는 것: "국세청 시스템이 너무 복잡", "XML 형식을 모름", "한 번 틀리면 반려됨", "매달 VAT 계산을 다시 해야 함"
- 현재 해결 방법: 국세청 홈택스 수동 입력, 세무 템플릿 활용, 세무사 상담 (월 5만원)
- 발생 빈도: 월 1회 (월말) 및 분기 1회 (VAT 신고)
- 시간 비용: 월 3-5시간 (세금계산서 작성), 분기 2-3시간 (VAT 신고)
- 금전 비용: 월 5만원 (세무사 상담), 오류 시 가산세 10-20%
- 문제 심각도 (0~10): 6
- 현재 지출: 월평 매출 1억~5억원 셀러, 세무 비용 월 5만원
- 소프트웨어 해결 가능성: 높음 (자동 XML 생성, 국세청 API 연동)
- AI 해결 가능성: 높음 (VAT 계산 자동화, 오류 감지)
- 1인 개발 가능성: 중간 (국세청 API 접근 권한 필요)

- 핵심 문제: 각 결제 프로세서가 서로 다른 정산 일정(2일, 5일, 주 1회), 수수료 구조(고정+변동), 환율 반영 방식(즉시/후일)을 가지고 있음. 오너는 실제 현금흐름이 언제 들어올지 예측할 수 없고, 캐시 플로우 계획이 불가능
- 사람들이 실제로 싫어하는 것: "정산금이 언제 들어올지 모름", "각 프로세서의 수수료가 다름", "현금흐름 예측이 불가능", "월말 자금 부족으로 급여 지급 지연"
- 현재 해결 방법: 각 프로세서 대시보드 확인, 엑셀에 정산 일정 정리, 회계사 상담
- 발생 빈도: 일 1회 (정산금 확인), 주 1회 (현금흐름 계획)
- 시간 비용: 주 2-3시간 (정산 추적, 캐시 플로우 계획)
- 금전 비용: 예측 불가능으로 인한 자금 관리 미스 (급여 지연, 투자 지연) 월 100만~1000만원 손실 가능
- 문제 심각도 (0~10): 7
- 현재 지출: 월평 거래액 5000만~5억원
- 소프트웨어 해결 가능성: 높음 (다중 결제 프로세서 통합, 현금흐름 예측)
- AI 해결 가능성: 높음 (결제 패턴 분석, 현금흐름 자동 예측)
- 1인 개발 가능성: 중간 (각 결제 프로세서 API 연동)
