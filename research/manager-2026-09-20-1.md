# Idea 001. 펫닥터 프라이스 (동물병원 영수증 공유 플랫폼)

## 한 줄 설명
실제 진료 영수증을 익명으로 업로드·검색해 병원별 진료비를 비교하고, 기여자에게 배지를 주는 반려동물 진료비 투명화 커뮤니티.

## 해결하는 Pain
P001 — 동물병원 진료비가 병원마다 최대 61~150배 차이나는데 사전 비교가 불가능.

## 제공하는 Positive Experience
S008(御朱印集め) 식 "방문 증거 수집+공유" 구조를 영수증 인증으로 변형. 기여할수록 지역 내 데이터가 쌓여 다음 이용자에게 도움이 된다는 이타적 성취감.

## Target User
반려동물 보호자(특히 수술·중증 진료를 앞두고 병원을 비교해야 하는 사람).

## 왜 설치하는가
"우리 동네 OO수술 평균가가 얼마인지" 검색하려고.

## 첫 30초
주소·진료항목 입력 → 지역 내 익명 영수증 기반 가격 분포 그래프 확인.

## 핵심 기능
영수증 사진 업로드(OCR 자동 항목 인식) → 항목 표준화 → 지역별 가격 분포 → 병원별 리뷰(가격 체감).

## 핵심 사용 루프
진료 후 영수증 업로드 → 커뮤니티 기여 배지 → 다음 진료 전 가격 검색 → 합리적 병원 선택 → 재이용 시 다시 업로드.

## 반복 사용 이유
반려동물을 키우는 한 진료가 반복되며, 매번 새로운 항목의 가격이 궁금해짐.

## Personalization
반려동물 종·크기·지역 기반 맞춤 가격 비교.

## AI 역할
영수증 이미지에서 진료 항목·금액 자동 추출 및 표준 항목명으로 정규화, 과잉진료 의심 항목 자동 하이라이트.

## Sharing
"바가지 쓸 뻔했다" 경험을 커뮤니티에 공유해 다른 보호자에게 경고하는 이타적 공유 동기.

## Monetization
프리미엄(상세 히스토리·병원 랭킹), 제휴 병원 리스팅 광고, 펫보험사 제휴 리드.

## MVP
특정 시술(슬개골 탈구, 스케일링 등) 몇 개 항목만으로 영수증 업로드+지도 기반 가격 비교 웹앱.

## MVP 예상 비용
약 250만원 이내(노코드/저코드 OCR API 활용).

## 가장 큰 약점
초기 데이터(영수증) 확보의 콜드스타트 문제. 기존 펫트라슈 등 경쟁 존재.

## 가장 중요한 검증 가설
사람들이 "바가지 쓴 경험"을 실명 없이도 기꺼이 업로드할 만큼 이타적 동기가 강한가?

# Idea 002. 관리비 감사관 (아파트 관리비 이상탐지+랭킹)

## 한 줄 설명
K-APT 공공데이터로 우리 단지 관리비를 유사 단지와 자동 비교하고, 이상 항목을 하이라이트해주는 매달 확인 습관형 서비스.

## 해결하는 Pain
P004 — 관리비 산출 내역이 불투명해 개인이 검증하기 어렵고, 정부조차 "기망·횡령일 수도 있다"고 지적.

## 제공하는 Positive Experience
S012(楽天経済圏) 식 "포인트/비용 최적화 공략 커뮤니티" 구조 — 우리 단지 vs 유사 단지 랭킹을 매달 확인하는 재미.

## Target User
아파트·오피스텔 입주민(자가·임차 무관).

## 왜 설치하는가
"우리 단지 관리비가 비싼 편인지" 확인하려고.

## 첫 30초
단지명 입력 → 유사 평형·연식 단지 대비 관리비 비교 그래프 즉시 표시.

## 핵심 기능
K-APT API 연동 자동 비교, 이상 급등 항목 알림, 이의제기 템플릿 자동 생성.

## 핵심 사용 루프
매달 고지서 발행 → 앱이 이상 항목 자동 알림 → 유사 단지 비교 확인 → (이상 시) 이의제기 템플릿 사용 → 다음 달 결과 확인.

## 반복 사용 이유
매달 발생하는 고정비이므로 월 1회 자연스러운 확인 루틴이 형성됨.

## Personalization
단지·평형·거주 형태별 맞춤 비교군 자동 매칭.

## AI 역할
전월 대비/유사 단지 대비 이상치 자동 탐지, 이의제기 문구 자동 생성.

## Sharing
"우리 단지 관리비 랭킹" 캡처를 입주민 단톡방에 공유하는 행동 유도.

## Monetization
프리미엄 상세 리포트, 관리비 컨설팅/이의제기 대행 제휴 수수료.

## MVP
K-APT 공공데이터 API + 단지 검색·비교 웹앱(입력 최소화).

## MVP 예상 비용
약 200만원 이내(공공데이터 API 무료).

## 가장 큰 약점
K-APT 데이터의 갱신 주기·정확도에 의존, 이상탐지가 실제 위법 여부를 보장하지 못함.

## 가장 중요한 검증 가설
"우리 단지가 비싼지 궁금하다"는 궁금증만으로 월 1회 재방문할 만큼 충분한 동기가 되는가?

# Idea 003. Dependency Digest (AI 그룹핑 의존성 업데이트 요약봇)

## 한 줄 설명
Dependabot이 쏟아내는 개별 PR을 AI가 위험도별로 그룹핑·요약해 주간 다이제스트 하나로 만들어주는 GitHub App.

## 해결하는 Pain
P015 — Dependabot 자동 PR이 그룹화 없이 하루에도 수십 개씩 쌓여 개발자 업무를 방해(GitHub Issue 원문으로 직접 확인된, 이번 조사에서 가장 근거가 강한 신호).

## 제공하는 Positive Experience
S019(GitHub Copilot) 식 "기존 워크플로우에 자연스럽게 녹아들어 손을 뗄 수 없게 되는" 습관화 경험.

## Target User
GitHub 저장소를 운영하는 개발팀·오픈소스 메인테이너.

## 왜 설치하는가
매일 쌓이는 Dependabot PR 노이즈를 당장 줄이고 싶어서.

## 첫 30초
저장소에 GitHub App 설치 → 즉시 기존 PR들이 위험도별로 그룹화된 대시보드로 재구성됨.

## 핵심 기능
변경 로그 AI 요약, 보안 취약점 여부 자동 플래그, 안전한 패치는 자동 병합 제안, 주간 배치 다이제스트.

## 핵심 사용 루프
주간 다이제스트 수신 → 위험도 높은 것만 리뷰 → 나머지 자동 병합 승인 → 다음 주 다이제스트.

## 반복 사용 이유
의존성 업데이트는 프로젝트가 살아있는 한 매주 발생하는 상시 작업.

## Personalization
저장소별 위험 허용도(자동 병합 기준) 설정.

## AI 역할
핵심 가치 자체가 AI 요약·위험도 평가 — AI 없이는 성립하지 않는 서비스.

## Sharing
README 배지("Dependency Digest 적용 중")를 통한 오픈소스 커뮤니티 내 자연 확산.

## Monetization
저장소당/조직당 월 구독(GitHub Marketplace 결제 연동), 오픈소스는 무료.

## MVP
GitHub App으로 Dependabot PR을 읽어 그룹화 요약 코멘트를 자동으로 다는 최소 기능.

## MVP 예상 비용
약 150만원 이내(1인 개발, LLM API 비용만 소요).

## 가장 큰 약점
GitHub 자체가 grouped updates 기능을 이미 자체 개선 중이라 플랫폼 리스크 존재.

## 가장 중요한 검증 가설
GitHub 공식 기능이 개선되어도 "AI 위험도 요약"이라는 별도 가치에 개발자가 돈을 낼 것인가?

# Idea 004. EV로드트립 올인원 (다중 충전 네트워크 통합 내비)

## 한 줄 설명
8개 이상으로 파편화된 미국/유럽 EV 충전 앱을 하나로 통합해 실시간 가용성·가격을 보여주고, AllTrails처럼 오프라인 지원과 여정 공유를 제공하는 구독형 로드트립 앱.

## 해결하는 Pain
P013 — EV 충전 앱이 8개 이상 파편화되어 로드트립마다 앱을 바꿔야 하고, 충전 시도의 약 1/5이 오류·고장.

## 제공하는 Positive Experience
S016(AllTrails) 식 "불안정한 환경에서도 작동한다는 신뢰 + 구독 결제 + 안전 목적 여정 공유".

## Target User
EV 장거리 로드트립 이용자(미국/유럽).

## 왜 설치하는가
다음 로드트립에서 또 여러 앱을 오가고 싶지 않아서.

## 첫 30초
목적지 입력 → 여러 네트워크를 아우른 최적 충전 스톱 경로 자동 생성.

## 핵심 기능
멀티 네트워크 실시간 가용성/고장 정보 통합, 단일 결제, 오프라인 경로 캐시, 동승 가족과 도착 예정시간 공유.

## 핵심 사용 루프
로드트립 계획 → 통합 경로+충전소 확인 → 실시간 상태 업데이트 → 도착 공유 → 다음 트립에도 재사용.

## 반복 사용 이유
EV 보유 기간 내내 로드트립마다 반복 필요.

## Personalization
차종별 충전 속도·배터리 상태 반영 경로 계산.

## AI 역할
실시간 가용성·고장 확률 예측, 최적 경로/충전시간 추천.

## Sharing
가족에게 도착 예정 시간 공유(Flighty와 유사한 안전 공유).

## Monetization
연 구독(AllTrails/Flighty 유사 가격대 벤치마크 필요 — Market 단계에서 검증).

## MVP

# Idea 010. 노콜 견적 (전화 없는 채팅 기반 차량 매입/견적)

## 한 줄 설명
한국 중고차 허위매물·일본 자동차 일괄견적 "전화폭탄" 문제를 동시에 겨냥해, 채팅/폼으로만 표준화된 견적을 받고 검증된 매물만 노출하는 서비스.

## 해결하는 Pain
P002(한국 중고차 허위매물) + P008(일본 자동차 일괄견적 전화폭탄) — 두 지역 모두 "차량 거래 정보 비대칭+원치 않는 영업 접촉"이라는 공통 구조.

## 제공하는 Positive Experience
S005(캐치테이블) 식 "원격으로 순서/결과를 관리하고 실제 이용자 리뷰로 신뢰를 쌓는" 경험.

## Target User
중고차를 사거나 팔려는 일반 소비자(한국), 車検/매각 견적을 받으려는 차량 소유자(일본).

## 왜 설치하는가
전화 응대 없이 견적/매물 정보를 확인하고 싶어서.

## 첫 30초
차량 정보 입력 → 채팅으로 표준화된 견적 요청서가 여러 업체에 동시 전송, 전화번호는 비공개.

## 핵심 기능
전화번호 마스킹, 채팅 견적 표준 양식, 허위매물 의심 이미지 역검색.

## 핵심 사용 루프
견적 요청 → 채팅으로 응답 수신 → 비교 → 마음에 들면 연결(전화번호 공개 동의).

## 반복 사용 이유
차량 매매는 개인당 빈도가 낮아 반복 사용 유인이 약함(주요 약점).

## Personalization
차종·연식 기반 예상 시세 자동 제시.

## AI 역할
매물 사진 역검색으로 허위매물(도용 사진) 탐지, 채팅 응답 표준화.

## Sharing
"이 매물 허위매물 의심" 신고를 커뮤니티와 공유.

## Monetization
업체(딜러·매입업체)로부터 리드당 과금.

## MVP
전화번호 비공개 채팅 견적 폼 + 이미지 역검색 기능 최소 구현.

## MVP 예상 비용
약 250만원(업체 네트워크 확보를 위한 초기 영업 비용은 별도).

## 가장 큰 약점
B2B2C 구조라 업체 네트워크 확보(영업)가 선행되어야 하며, 1인 개발로는 공급 측 확보가 어려움. 사용 빈도 낮음.

## 가장 중요한 검증 가설
업체들이 "전화 없이 채팅으로만" 응대하는 방식에 동참할 유인이 있는가(리드 품질이 오히려 낮아질 수 있음)?

# Idea 011. 놓치지마 (한국·일본 육아지원금+보육원 신청 통합 도우미)

## 한 줄 설명
가구 상황을 입력하면 한국의 파편화된 육아지원금과 일본 保活(보육원 신청) 점수·전략을 자동으로 정리해 마감일을 놓치지 않게 해주는 서비스.

## 해결하는 Pain
P005(한국 육아지원금 파편화) + P007(일본 保活 점수계산 복잡) — "정보 파편화로 인해 고액의 기회를 놓친다"는 공통 구조.

## 제공하는 Positive Experience
S010(ふるさと納税) 식 "챙기지 않으면 손해"라는 프레이밍 + 매년/매 시기 반복되는 리마인드형 리피트 구조.

## Target User
임신~영유아 자녀를 둔 부모(한국), 保活을 앞둔 맞벌이 부모(일본).

## 왜 설치하는가
"내가 받을 수 있는 지원금/전략을 놓치고 있는 건 아닌지" 확인하려고.

## 첫 30초
거주지·출산예정일·가구 상황 입력 → 해당하는 지원금 목록과 신청 마감일, 혹은 보육원 예상 점수 즉시 표시.

## 핵심 기능
지자체별 지원금 자동 매칭, 마감일 알림, (일본) 保活 점수 계산기 + 지원 어린이집 수 추천.

## 핵심 사용 루프
가입 시 상황 등록 → 마감일 다가올 때 알림 → 신청 완료 체크 → 자녀 성장에 따라 다음 지원금 알림.

## 반복 사용 이유
임신~영유아기 동안 여러 시점(출생신고, 첫만남이용권, 보육원 신청 등)에 반복적으로 알림이 발생.

## Personalization
가구 소득·자녀 수·거주 지자체에 따라 결과가 완전히 달라짐 → 개인화 핵심 그 자체.

## AI 역할
지자체별 공고문(비정형 텍스트)을 파싱해 자동으로 조건 매칭.

## Sharing
맘카페에 "이거 몰랐는데 이 앱으로 알았다" 형태로 공유될 여지.

## Monetization
지자체/기업 육아복지 제휴 광고, 프리미엄 맞춤 상담 연결.

## MVP
한국 대표 지원금 5~10개 항목의 조건·마감일을 DB화한 웹 체크 서비스로 시작(일본 保活는 2단계).

## MVP 예상 비용
약 250만원 이내.

## 가장 큰 약점
정부 정책이 자주 바뀌어 데이터 유지보수 부담이 크고, 정부24 등 기존 채널과 기능이 일부 겹침.

## 가장 중요한 검증 가설
"기한을 놓쳤다"는 뉴스 사례가 실제로 얼마나 흔한 일인지(전체 부모 대비 비율)와, 그 정보 격차를 이 서비스가 실제로 메울 수 있는가?

# 가장 중요한 관찰

1. **가장 강한 아이디어(I003 Dependency Digest)는 근거 자체도 가장 강했다.** Negative Agent가 유일하게 원문(GitHub Issue)을 WebFetch로 직접 확인한 신호(P015)에서 나왔다 — 원문 근거의 질이 곧 아이디어 품질로 이어진다는 것을 보여주는 사례.
2. **"정보 비대칭 + 비교/투명화" 패턴(I001, I002)**이 한국 시장에서 반복적으로 발견된다(어제는 배달앱 정산, 오늘은 동물병원·관리비). 이 패턴 자체가 하나의 지속적 탐색 축이 될 수 있다.
3. **1회성 이벤트형 Pain(I005 헬스장 해지, I008 이사, I010 차량매매)은 Pain 강도는 높지만 Retention/사용빈도 점수가 구조적으로 낮다.** Manager 규칙상 이런 아이디어는 아무리 Pain이 강해도 B등급 이상을 받기 어렵다 — Market Agent는 이들을 "성과보수/원타임 결제" 모델로만 검토할 것을 권장.
4. 이번 회차는 (어제와 달리) 20+20 목표를 완전히 달성해 아이디어 다양성이 컸으나, WebFetch 차단으로 원문 1차 인용이 부족한 신호가 많아(P015 제외) 개별 아이디어의 근거 신뢰도는 제한적이다.
