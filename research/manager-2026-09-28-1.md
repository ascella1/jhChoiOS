# Idea 001. Return Express (반품 자동화 & 환불 추적)

## 한 줄 설명
온라인 쇼핑의 반품 배송비 부담과 환불 지연을 없애고, 실시간 환불 추적과 배송비 무료화를 보장하는 자동화 플랫폼

## 해결하는 Pain
P001: 온라인 쇼핑 반품 배송비 부담 (월 3~20만원) 및 5~10일 환불 지연

## 제공하는 Positive Experience
- MyFitnessPal의 자동 계산 (반품 배송비 자동 비교·최저가 선택)
- Strava의 실시간 진행도 (반품 상태 리얼타임 추적)
- Goodreads의 커뮤니티 공유 ("반품 완료 후 판매처별 비용 비교 공유")

## Target User
온라인 쇼핑 월 2회 이상, 의류·신발 주요 구매 직장인 (25~45세, 월 소득 400만원 이상)

## 왜 설치하는가
"반품 한 번에 1만원 손실하지 않아도 되고, 환불이 언제 올지 매일 확인할 수 있다"

## 첫 30초
앱 실행 → 반품할 상품 사진 촬영 → "반품 비용 계산 중..." → 판매처별 배송료 비교 (쿠팡 5,000원 vs 무신사 무료) → "가장 싼 배송사 선택" 클릭 → QR 코드 자동 생성

## 핵심 기능
1. **배송비 최적화**: 판매처·배송사별 반품 배송료 실시간 비교 & 자동 선택
2. **환불 추적**: 반품 접수부터 환불 완료까지 단계별 실시간 업데이트
3. **환불 예측**: ML로 판매처별 환불 소요 일수 예측 ("3일 후 환불")

## 핵심 사용 루프
Trigger → 상품 불량/맞지 않음 알림 → Action: 앱에서 반품 신청 (2분) → Reward: 배송비 비교 화면에서 절약액 시각화 ($5 saved!) → Investment: 배송 및 환불 추적 → Next Trigger: 주간 환불 요약 푸시

## 반복 사용 이유
- 월 1~2회 반품 필요 시 자동으로 돌아옴
- "이번 반품은 배송료 무료일까?" 기대감
- 환불 예정일 3일 전 리마인더 → 기대감 증대

## Personalization
- 사용자의 반품 이력 학습 → "당신은 보통 3일 후 환불받아요"
- 선호 배송사 학습 ("쿠팡 로켓배송 반품만 선택")
- 판매처별 환불 실적 기록 (삼성 VS 쿠팡 환불 속도 비교)

## AI 역할
- 배송료 최적화: 판매처·배송사 조합별 가장 저렴한 루트 추천
- 환불 예측: 판매처·상품 카테고리별 평균 환불 일수 예측
- 분쟁 자동화: OCR로 반품 규정 자동 해석 ("불량 판정 가능성 85%")

## Sharing
- 주간 "반품 절약액" 리포트 SNS 공유 ("이번주 배송료 2,500원 절약!")
- 판매처별 환불 속도 비교표 친구 공유
- 커뮤니티: "삼성 반품, 쿠팡이 빠를까 무신사가 빠를까?" 투표

## Monetization
- 기본: 무료 (배송사 제휴 수수료 1%)
- 프리미엄: $4.99/월 (우선 환불 처리 + 고객센터 지원)
- B2B: 판매처 대시보드 ($999/월, 반품 분석)

## MVP
1. 쿠팡·무신사·11번가 3개 플랫폼 연동
2. 반품 배송료 비교 엔진
3. 반품 상태 추적 (배송 시작 → 상품 수령 → 환불)
4. 주간 절약액 요약

## MVP 예상 비용
₩4,000,000 (4개월, 2명 개발자)

## 가장 큰 약점
- **경쟁사**: 쿠팡 자체 "반품 배송료 지원" 정책이 강력함 (일부 상품)
  - 차이점: Return Express는 "모든 판매처 통합" vs 쿠팡은 "쿠팡 내부만"
- 판매처 API 연동 거부 가능성
- 배송사와의 제휴 협상 복잡성

## 가장 중요한 검증 가설
- **H1**: 사용자가 월 1회 이상 반품할 때 이 앱을 사용할까?
- **H2**: 배송료 비교가 실제로 의사결정에 영향을 미칠까? (A/B 테스트: 비교 화면 vs 미비교)
- **H3**: 판매처·배송사가 API 개방에 동의할까?

# Idea 002. Ride Reliability Shield (신뢰도 기반 카풀 매칭)

## 한 줄 설명
카풀 기사 취소를 줄이기 위해 신뢰도 스코어와 "취소 0 스트릭"을 시각화하는 카풀 오버레이 플랫폼

## 해결하는 Pain
P002: 카풀 기사 취소로 인한 주 1~2회 시간 낭비 (5~15분 지연)

## 제공하는 Positive Experience
- Strava의 신뢰도 점수 시각화 (기사 취소율 실시간 표시)
- Habicat의 스트릭 시스템 ("이 기사는 취소 0 스트릭 30일")
- Discord Economy Bot의 리더보드 (신뢰도 높은 기사 TOP 5)

## Target User
출퇴근 직장인 (25~50세, 주 2회 이상 카풀/택시), 정시 도착 중요

## 왜 설치하는가
"기사를 선택할 때 '이 기사는 절대 취소 안 한다'는 거 한눈에 보고 싶어"

## 첫 30초
카카오맵/네이버맵에서 카풀 호출 → Shield 오버레이 실행 → 기사 3명 목록 표시 → 각 기사별 신뢰도 점수 (기사A: 98점, 취소 0 스트릭 45일) → 신뢰도 높은 기사 선택

## 핵심 기능
1. **기사 신뢰도 스코어**: 취소율, 평가, 지연율 기반 0~100점
2. **취소 0 스트릭**: 연속으로 취소 없는 날수 시각화
3. **신뢰도 기반 배치**: 우선 신뢰도 높은 기사에게 요청 전달

## 핵심 사용 루프
Trigger → 카풀 필요 알림 → Action: Shield 앱에서 신뢰도 기사 선택 (30초) → Reward: 신뢰도 높은 기사 매칭 성공 → Investment: 차량 탑승 → Next Trigger: 주간 "취소 회피" 통계

## 반복 사용 이유
- 매일 2회 (출·퇴근) 신뢰도 기사를 찾는 습관화
- "이 기사는 스트릭이 50일째"라는 신뢰감

## Personalization
- 사용자 위치별 신뢰도 높은 기사 추천
- 선호 차량 타입·기사 성별 학습
- "당신의 선호 기사" 즐겨찾기 기능

## AI 역할
- 취소 위험 예측: "이 기사는 오후 4~5시에 취소율 높음" 경고
- 신뢰도 점수 계산: 취소율, 평가, 도착 시간 정확도 가중치 모델
- 기사 매칭 최적화: 사용자 위치 + 기사 신뢰도 + 기사 방향성 조합

## Sharing
- 주간 "취소 회피 성공" 통계 SNS 공유 ("이주 카풀 취소 0회!")
- 신뢰도 기사 공유 ("우리 동네 최고의 기사 TOP 3")
- 커뮤니티: 지역별 신뢰도 기사 리뷰

## Monetization
- 기본: 무료 (카풀앱 광고 수익 공유)
- 프리미엄: $2.99/월 (우선 신뢰도 기사 예약)
- B2B: 카풀사 데이터 제공 (기사 성과 관리 도구)

## MVP
1. 카카오맵 카풀만 연동 (API)
2. 기사 신뢰도 점수 계산 (취소율, 평가)
3. 스트릭 시각화
4. 신뢰도 높은 기사 우선 표시

## MVP 예상 비용
₩2,500,000 (3개월, 1명 개발자)

## 가장 큰 약점
- **경쟁사**: 카카오맵·네이버맵·타다가 이미 "기사 평가" 기능 보유
  - 차이점: Shield는 "취소율 특화" + "스트릭 게임화" (기존은 일반 평가만)
- 기사 데이터 접근 권한 필요
- 신뢰도 조작 가능성 (기사가 다른 계정으로 자신 평가)

## 가장 중요한 검증 가설
- **H1**: 취소율 정보가 실제 기사 선택에 영향을 미칠까?
- **H2**: 스트릭 시스템이 기사의 취소 행동을 줄일까?
- **H3**: 기사들이 이 서비스에 협력할까? (데이터 공개)

# Idea 003. Expense Auto-Logger (영수증 자동 인식 & 경비 분류)

## 한 줄 설명
출장 경비의 영수증 스캔·입력·분류를 완전 자동화하고, 월별 경비 추이를 대시보드로 시각화하는 AI 앱

## 해결하는 Pain
P012 (일본 회사, 월 1~2시간), P014 (글로벌, 월 5~10시간 관리자): 영수증 스캔·수동 입력·분류 번거로움

## 제공하는 Positive Experience
- MyFitnessPal의 자동 인식 (음식 사진 → 자동 칼로리 계산)
- Strava의 실시간 자동 기록 (GPS 자동 로깅)
- Goodreads의 데이터 시각화 (월별 읽은 책 수 그래프)

## Target User
출장 월 2회 이상 직장인 (30~55세), 기업 경비 담당자

## 왜 설치하는가
"영수증 사진 찍으면 자동으로 분류되고, 달서 경비 요약이 뜨면 좋겠어"

## 첫 30초
앱 실행 → 영수증 사진 촬영 → "인식 중..." → 자동 분류 완료 ("음식비", "교통비", "숙박비") → "경비 추가 완료" 확인 → 월별 차트 표시

## 핵심 기능
1. **OCR 자동 인식**: 영수증 사진 → 금액·항목·날짜 자동 추출
2. **AI 자동 분류**: 영수증 내용 → 음식/교통/숙박/기타 자동 분류
3. **다국어 지원**: 한국·일본·영어 영수증 동시 인식
4. **월별 대시보드**: 경비 카테고리별 그래프 + 전월 비교

## 핵심 사용 루프
Trigger → 식사·택시·호텔비 결제 → Action: 영수증 사진 (3초) → Reward: 자동 분류 확인 → Investment: 월말 정산 → Next Trigger: 월별 경비 추이 리뷰

## 반복 사용 이유

1. **EHR 통합 수집**: 여러 병원·약국 기록 자동 수집 & 통합
2. **약물 상호작용 체크**: 모든 약물 목록 표시 + 상호작용 경고
3. **의사 권한 공개**: 진료 시 의사에게 즉시 기록 공개 (환자 승인 필요)
4. **중복 검사 방지**: "이미 1주일 전 혈액검사 했으니 재검사 불필요" 경고

## 핵심 사용 루프
Trigger → 새 병원 예약 → Action: 앱에서 "이 병원에 기록 공개" 승인 (30초) → Reward: 의사가 과거 기록 참고해서 진료 시간 50% 단축 → Investment: 진료 → Next Trigger: 새 진단 기록 자동 추가

# 가장 중요한 관찰

## 1. Pain → Positive 변환 구조
이번 조사에서 발견한 핵심 패턴은 **"수작업 → 자동화"** 아닌 **"불확실성 → 시각화"**이다.

- Negative signal들 (P001~P020)은 모두 "답을 모르는 상태": 언제 반품금이 올까? 기사가 취소할까? 보험 청구는 언제 끝날까?
- Positive signal들 (S001~S020)은 모두 "시각화된 진행도": Strava의 거리 그래프, MyFitnessPal의 칼로리 진행도, Goodreads의 챌린지 진행율

**따라서 가장 유망한 Pain은 "진행 상황이 불명확한" 프로세스이다**.

## 2. Portfolio 다양성 확보
- **S-Grade (1개)**: Expense Auto-Logger (자동화 + AI 특화, 가장 완성도 높음)
- **A-Grade (8개)**: Return Express, Ride Shield, Real-Time Reservation, Insurance Speedrun, Payment Guardian, Freelancer Safe, Meeting Sync, 경비 관리 (기술적 난이도와 시장성 균형)
- **B-Grade (3개)**: Account Recovery, Work Hours, Shift Pay (시장 규모 작거나 규제 복잡)
- **C-Grade (1개)**: Student Finance (매우 낮은 사용 빈도, 검증 어려움)

## 3. 뜨는 패턴: "완전 자동화"
기존 경쟁사들 (Concur, Xero, Otter.ai)은 "반자동"을 제공: 사용자가 여전히 버튼을 눌러야 함.

**차세대 제품은 "버튼도 누르지 않음"**:
- Expense Auto-Logger: 사진만 찍으면 자동 분류 (Concur는 수동 분류 여전히 필요)
- Work Hours Autopilot: 아무것도 하지 않음 (자동 감지)
- Meeting Transcript Sync: 플러그인 설치 후 0개입 (자동 기록)

이러한 "0-click automation" 접근이 **Positive signal (Strava, MyFitnessPal)과 일치**한다.

## 4. AI의 핵심 역할: "예측"이 아닌 "자동화"
조사 초반에는 AI를 "예측"에 사용하려 했으나 (환율 예측, 취소 위험 예측), 실제 Positive signal들에서 AI의 역할은:

1. **OCR/자동 분류** (MyFitnessPal, Expense Logger)
2. **실시간 동기화** (Strava, Goodreads)
3. **이상 탐지** (MyFitnessPal: "칼로리가 평년의 200% 높음")

**따라서 AI는 "예측"보다 "자동화 + 이상 탐지"에 집중해야 함**.
