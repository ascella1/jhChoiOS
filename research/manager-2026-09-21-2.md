# Idea 001. 예약 시간 충격 (Appointment Wait Guarantee)

## 한 줄 설명
병원 예약 후 실제 진료까지 대기시간이 예약시간+30분 이상 초과 시, 다음 진료에 자동으로 할인쿠폰 제공하는 서비스.

## 해결하는 Pain
P001 — 병원 예약 후에도 1시간 이상 초과 대기 (예약의 의미가 없다는 좌절감)

## 제공하는 Positive Experience
야놀자식 "월별 할인 쿠폰" + 쿠팡와우식 "이미 낸 돈, 본전뽑기" 심리 결합. 초과 대기 시 자동 보상으로 "다음에는 이 할인으로 이용해야지"라는 기대감 형성.

## Target User
대학병원/종합병원을 자주 방문하는 만성질환자, 정기검진자.

## 왜 설치하는가
"우리 병원 평균 대기시간이 얼마나 되고, 초과 시 뭘 받는지" 투명하게 알기 위해.

## 첫 30초
예약 병원/과/시간 입력 → "평균 진료까지 시간 20분 예상, 30분 초과 시 1만원 쿠폰" 확인.

## 핵심 기능
1. 병원별 실시간 대기시간 데이터 수집 (의료기관 자발적 API 제공 또는 사용자 체크인)
2. AI 기반 대기시간 예측 (요일·시간대·계절별 패턴)
3. 실제 진료 시간 vs 예약시간 차이 자동 계산
4. 초과 시 자동 할인쿠폰 발급 (다음 진료/의약품 구매)

## 핵심 사용 루프
예약 확인 → 앱에서 평균 대기시간 확인 → 실제 진료 → 초과 시 쿠폰 자동 발급 → 다음 진료 시 할인 사용

## 반복 사용 이유
병원을 자주 방문하는 사용자는 매번 "이번엔 몇 분 초과할까" 궁금해하고, 누적 쿠폰이 실질적 가치가 됨.

## Personalization
개인별 방문 병원 즐겨찾기 → 해당 병원의 대기시간 알림 설정 가능.

## AI 역할
- 의료기관별 시간대별 대기시간 패턴 학습 (과거 데이터 누적)
- "목요일 오후 3시는 대기 50분" 같은 예측
- 초과 쿠폰 액수를 대기 시간에 비례해 동적 결정 (30분 초과 vs 1시간 초과 차별화)

## Sharing
"이 병원 진짜 대기 오래네, 쿠폰으로라도 보상받자" → 친구에게 팁 공유 (커뮤니티 신뢰도 강화).

## Monetization
1. **Performance Fee (핵심)**: 병원이 초과 시 발생하는 할인쿠폰 가치의 20% 수수료. 즉, "약속을 지킨" 병원은 수수료 없음.
2. 프리미엄: 월정액으로 모든 병원의 대기시간 알림 구독
3. 제휴: 의약품 배송사 (의약품 구매 쿠폰으로 변환)

## MVP
특정 지역(서울) + 특정 진료과(내과, 정형외과) 몇 개만 → 사용자 수동 체크인 기반 대기시간 수집 → 웹앱 기반 대시보드.

## MVP 예상 비용
약 300만원 (백엔드 + 프론트엔드, 데이터 수집 자동화 제외 수동시작).

## 가장 큰 약점
1. **콜드스타트**: 초기 대기시간 데이터 부족. 의료기관 협력 필수.
2. **의료기관 의사결정**: 병원이 "우리 대기시간을 공개한다"는 경영 결정이 필요 (명시적 데이터).
3. **Platform Risk**: 닥터나우 등이 이미 대기시간 기능을 가지고 있으며, 대형 플랫폼이 통합할 가능성.

## 가장 중요한 검증 가설
1. 사람들이 "대기시간 초과 시 자동 보상"이라는 개념에 매력을 느끼는가?
2. 병원이 자신의 평균 대기시간을 공개할 만큼 신뢰도가 높은가?

# Idea 002. 주차보증 앱 (Parking Guarantee)

## 한 줄 설명
주차 예약 후 10분 이내 주차를 보장하고, 초과 시 배송앱 쿠폰으로 보상하는 주차 통합 플랫폼.

## 해결하는 Pain
P002 — 도시에서 주차장 찾기에 10~20분 낭비, 예약앱도 번거로움 (스트레스 + 시간손실).

## 제공하는 Positive Experience
쿠팡와우식 "절감 체감" + 야놀자식 "마감할인" 결합. "10분 내 주차" 보증으로 심리적 안정감 + 초과 시 배송비 절감으로 별도 보상.

## Target User
도시 지역에 자주 방문하는 자동차 운전자 (쇼핑, 병원, 업무 방문).

## 왜 설치하는가
"이 주차장 가면 진짜 10분 안에 주차할 수 있나?" 확인해서 약속 시간을 지키기 위해.

## 첫 30초
목적지 입력 → "근처 예약 주차 3곳" + "평균 10분 보증" 표시 → 1탭 예약.

## 핵심 기능
1. 주차장 공급자 통합 (i-Parking, KakaoT 등의 실시간 공실 정보 수집)
2. "10분 보증" 정책 (초과 시 자동 보상)
3. 배송쿠폰 연동 (보상으로 배송비 할인 제공)

## 핵심 사용 루프
도착 전 주차 예약 → 실제 주차 → 10분 초과 시 배송쿠폰 자동 발급 → 다음 배송에 할인 사용

## 반복 사용 이유
도시 거주자는 매주 여러 번 주차하므로, "이 주차장은 항상 빠르다"는 신뢰 형성 후 반복 이용.

## Personalization
자주 방문하는 장소별 평가 기록 (사무실, 병원, 쇼핑몰 등) → 맞춤 추천.

## AI 역할
- 시간대별 주차 혼잡도 예측 (요일·시간·날씨 기반)
- "11:00~12:00은 혼잡, 예상 10분 초과 위험" 알림
- 주차장별 평균 소요시간 학습

## Sharing
"여기서 10분 보증받고 배송쿠폰 얻었어" → 친구에게 추천.

## Monetization
1. **Performance Fee (핵심)**: 주차장사업자가 10분을 못 지켰을 때만 배송쿠폰 보상. 쿠폰 가치의 15% 수수료.
2. 배송앱 제휴 커미션 (배송쿠폰 사용 시 일부 수익)
3. 프리미엄: 월정액 구독 (추가 보증 금액 + 우선예약).

## MVP
특정 도시(서울 강남역 주변) + 주차장 5~10곳만 시작 → 사용자 실제 주차 시간 기록 → 웹/앱 통합.

## MVP 예상 비용
약 280만원 (주차장 데이터 파싱 + 배송앱 API 연동 + 보상 시스템).

## 가장 큰 약점
1. **주차장 협력 필수**: 공실 정보와 실제 주차 시간을 수집해야 하는데, 주차장 사업자 협력이 필수.
2. **배송쿠폰 가치 변동성**: 배송 쿠폰의 실제 사용률이 낮을 수 있음.
3. **Platform Risk**: 카카오T, i-Parking 같은 대형 플랫폼이 이 기능을 자체 추가할 가능성.

## 가장 중요한 검증 가설
1. 사람들이 "10분 보증"에 월 2회 이상 주차할 의지가 있는가?
2. 주차장 사업자가 10분 보증을 받아들일 만큼 경영 여유가 있는가?

# Idea 003. 카드거절 패턴분석기 (Card Decline Analyzer)

## 한 줄 설명
신용카드 거절 이유를 AI로 분석해 "FDS vs 한도초과 vs 해외결제" 중 원인을 추측하고, 다음 거절 예상 시나리오를 알려주는 앱.

## 해결하는 Pain
P003, P008 — 신용카드 거절 이유를 카드사가 알려주지 않아, 사용자가 답답함.

## 제공하는 Positive Experience
마네포ME식 "자동 수집 + 분석" + Discord식 "개인화된 인사이트" 결합. "내 거절 패턴"을 시각화해 다음 거절을 예방하는 능력감.

## Target User
국내·해외 결제를 자주 하는 사람 (온라인 쇼핑, 해외구매, 구독서비스).

## 왜 설치하는가
"지금 이 카드가 왜 거절됐는지" 즉시 알아서 다른 카드로 대체하거나, 대기 후 재시도할 수 있도록 하기 위해.

## 첫 30초
최근 거절된 카드 거래 입력 (금액·시간·지역) → "예상 원인: FDS 이상거래 탐지 80%" + "대기 2시간 후 재시도 추천" 표시.

## 핵심 기능
1. 거절된 거래 정보 수집 (카드사 알림 스크린샷 또는 카드사 API)
2. AI 패턴 분석 (FDS, 한도초과, 해외결제 차단, 연체 등 구분)
3. 예상 원인별 대응법 제시 ("카드사에 신고", "해외거래 사전신청", "한도 확인" 등)
4. 예측 알림 (다음 주 해외출장 → "이 카드는 해외거래 미등록, 선제적 신청 필요")

## 핵심 사용 루프
카드 거절 → 앱에 기록 → AI 원인 분석 → 대응법 제시 → 다음 거절 예방 → 신뢰도 증가 → 매번 기록

## 반복 사용 이유
거절 경험이 반복되는 사용자(국제결제, 고액구매)는 매번 "이번엔 무슨 원인?" 궁금해서 앱을 열음.

## Personalization
개인별 거절 패턴 학습 (예: "이 사람은 매월 1회 FDS 거절, 매분기 해외거래 차단") → 패턴별 맞춤 알림.

## AI 역할
- 거절 메타데이터 (금액, 시간, 지역, 카드사)에서 원인 추론
- "오후 10시 대형마트 해외카드는 보통 FDS 의심" 같은 패턴 학습
- 예측: "다음 주 미국 출장 예정 → 카드사에 해외거래 사전 신청 필수" 알림

## Sharing
"카드 거절 이유 분석 앱 덕분에 해외거래 미리 신청했어" → 친구 추천 (신뢰 기반).

## Monetization
1. 프리미엄: 월정액 (AI 상세 분석, 예측 알림 고도화)
2. 카드사 제휴: 카드사가 사용자 거절 패턴을 익명 통계로 활용 (B2B 수익)
3. 은행 제휴: 한도 상향 추천 → 제휴 수수료

## MVP
카드 거절 이유를 사용자 수동입력 방식으로 수집 → 기본 분류 (FDS / 한도 / 해외) → AI는 간단한 rule-based 분류 시작.

## MVP 예상 비용
약 250만원 (백엔드 + 분류 AI + 프론트엔드, 카드사 API 연동 제외).

## 가장 큰 약점
1. **데이터 프라이버시**: 거절 정보가 개인식별 정보이므로 규정상 제약 많음.
2. **AI 정확도**: 카드사 내부 FDS 로직은 블랙박스라 추론만 가능 (확실한 답이 아님).
3. **Platform Risk**: 카드사 자체가 앱을 개선해서 거절 이유를 직접 제시할 가능성.

## 가장 중요한 검증 가설
1. 사람들이 "추론된 원인"을 신뢰할 만큼 신뢰도가 높은가?
2. 실제로 매달 카드 거절이 발생하는 사람이 target market에 충분한가?

# Idea 004. 공사진도 AI 추적 (Construction Progress AI)

## 한 줄 설명

## 해결하는 Pain
P004 — 인테리어 공사가 예상보다 길어지고 추가 비용 발생 ("계약에 없던 비용이 자꾸 늘어난다").

## 제공하는 Positive Experience

## Target User
아파트/주택 인테리어 발주자 (특히 대공사 대상자).

## 왜 설치하는가
"우리 공사 진짜 진행 중인가" 하루하루 확인하고, "혹시 추가비용 나올까"를 미리 예측하기 위해.

## 첫 30초

## 핵심 기능
1. 공사현장 사진 자동 분석 (AI 객체탐지: 철거/벽/도배/타일/페인트 등 공정 단계 인식)
2. 진행도 % 자동 계산 (일일 누적 진도 추적)

4. 추가비용 경고 (공사 계획에 없던 작업 탐지 → "철거 후 곰팡이 제거 발견?" 알림)

## 반복 사용 이유

## Personalization

2. 공사업체 제휴: 업체가 고객에게 "진도 추적 앱"으로 투명성 마케팅 활용
3. 건설보험 제휴: 공사 이력 데이터 제공 (개인식별 정보 제거)

# Idea 005. 진료비 명세서 자동검증 (Medical Bill Auto-Audit)

실손의료보험을 가진 모든 환자 (특히 고액 진료, 복합 질환자).

## 한 줄 설명

## 해결하는 Pain

## Target User
월 데이터 사용량이 변동성 큰 사람 (일부는 3GB, 일부는 12GB).

## 왜 설치하는가
"다음 달에 내 데이터가 몇 GB 쓸 것 같으니 요금제를 미리 정하기" 위해.

## 첫 30초

# Idea 009. 신용카드 자동최적화 (Card Optimization Engine)

## 한 줄 설명
여러 신용카드 자동 연동 → 카테고리별 지출 분석 → "이 달에는 X카드가 최고 캐시백" 자동 추천 + 다음달 최적 카드 추천.

## 해결하는 Pain
P006(요금 예측), P014(다중 계정 피로도) → 카드 결정 시간·피로도 줄이기.

## 제공하는 Positive Experience
마네포ME(자동수집+분석+개인화) 결합. 단순히 "기록"이 아니라 "최적 결정"을 AI가 대신해주는 느낌.

## Target User
3개 이상의 신용카드를 가지고 있지만, "어느 카드를 써야 할지" 고민하는 사람.

## 왜 설치하는가
"이 달 카테고리별 지출을 고려하면 어느 카드를 써야 최고 캐시백을 받을지" 알기 위해.

## 첫 30초
카드 3개 등록 (각 카드의 캐시백 조건 자동 인식) → 지난달 지출 입력 → "당신은 이 달 음식비 30만원 쓸 것 같으니, A카드(음식 5%)로 통일하면 15,000원 절약" 제안.

## 핵심 기능
1. 여러 카드 자동 연동 (또는 수동 입력)
2. 각 카드의 캐시백 조건 자동 인식 (또는 사용자 입력)
3. 지출 카테고리 자동 분류 (음식/교통/쇼핑 등)
4. 월별 최적 카드 제안 (캐시백 최대화)
5. 실제 결제 시 "이 카테고리는 X카드" 알림

## 핵심 사용 루프
카드 등록 → 지난 3개월 지출 분석 → "다음달 최적 카드 조합" 제시 → 실제 결제 시 알림 → 개인화 개선 → 월별 추천 업데이트

## 반복 사용 이유
매달 카테고리별 지출이 변하므로, "이번 달은 어느 카드를 써야 할까" 앱을 월 1회 이상 확인.

## Personalization
개인 지출 패턴 학습 (예: 당신은 매달 음식비 30만원, 교통비 10만원) → 그에 맞는 카드 조합 최적화.

## AI 역할
- 지출 자동 분류 (NLP로 상품명→카테고리)
- 카드별 캐시백 규칙 학습 (자동 업데이트)
- 월별 예상 지출 예측 (계절별, 휴일별)
- 캐시백 최대화 알고리즘 (조합 최적화)

## Sharing
"이 앱으로 월 3만원 더 절약했어" → 친구 추천.

## Monetization
1. 프리미엄: 월정액 (고급 분석, 수동 카드 결제 추적)
2. 신용카드사 제휴: "최적 카드 추천" 데이터 제공 (개인식별 제거) → 신카사가 고객에게 마케팅 활용
3. 은행 제휴: "당신 지출 패턴에 최고 카드" 추천 → 신규 카드 발급 유도 (수수료)

## MVP
카드 2~3개 연동 + 기본 카테고리 분류 (수동) + 간단한 캐시백 계산 (엑셀 수준).

## MVP 예상 비용
약 250만원 (백엔드 + 카드사 데이터베이스 구축 + 프론트엔드).

## 가장 큰 약점

2. **실제 카드 결제 자동 전환 불가**: 법제도상 "자동으로 다른 카드로 결제" 기능은 불가능.
3. **Platform Risk**: 토스, 신한카드 같은 대형 플랫폼이 자체 기능으로 추가할 가능성.

2. 실제로 "AI 추천"에 따라 카드를 바꿔서 사용하는가? (알림만으로는 부족할 수 있음)

## Target User
스마트폰 보안에 관심 있는 모든 사용자 (특히 프라이버시 민감층).

## 왜 설치하는가
"내 폰의 어느 앱이 내 위치를 추적하는지" 알고 차단하기 위해.

## 첫 30초
권한 스캔 시작 → "위치: 8개 앱 허용 (위험 3개)" / "카메라: 5개 앱 허용" 요약 → "위험" 앱 3개 목록.

## 핵심 기능
1. 설치된 앱 전체 권한 스캔 (위치, 카메라, 마이크, 연락처 등)
2. "위험한 권한" 자동 감지 (예: 게임 앱이 위치 권한 요청)
3. 한 번의 클릭으로 권한 해제 (폰 설정으로 직접 이동)
4. 월간 권한 리포트 (어떤 앱이 얼마나 데이터를 수집했는지)

## 핵심 사용 루프
앱 설치 → 앱 권한 스캔 → "위험 권한" 발견 → 클릭으로 차단 → 월간 리포트 확인

## 반복 사용 이유
새로운 앱을 설치할 때마다 "이 앱이 위험한 권한 요청하지 않나" 앱으로 체크.

## Personalization
개인의 프라이버시 선호도 학습 (예: "이 사람은 모든 위치 권한 차단 선호") → 자동 제안.

## AI 역할
- 앱별 권한의 위험도 자동 판단 (게임에 위치권한은 "의심", 카메라는 "정상")
- 권한 요청 시기 분석 (앱 실행 중 vs 백그라운드 → 의심도 판단)

## Sharing
"이 앱 위치 권한 요청하네, 차단하자" → 친구에게 조언.

## Monetization
1. 프리미엄: 월 2,000원 (고급 분석, 자동 차단 기능)
2. 기업 B2B: 기업이 직원 스마트폰 권한 관리 (MDM 솔루션)
3. OS 차원 제휴: Apple/Google이 플랫폼에 통합 가능성 있으나, 별도 앱으로도 수익 가능

## MVP
권한 스캔 + 위험도 기본 판단 + 폰 설정 링크 (실제 자동 해제는 기술적 제약).

## MVP 예상 비용
약 200만원 (권한 스캔 API + 위험도 규칙 + 프론트엔드).

## 가장 큰 약점
1. **기술 제약**: 앱 권한을 "자동으로" 해제하는 것은 OS 수준에서 제약 있음 (사용자 수동 클릭 필요).
2. **Platform Risk**: Apple/Google이 OS 자체에 내장할 가능성 높음 (이미 일부 기능 존재).
3. **반복 사용 동기 약함**: 권한 설정은 보통 1회만 하므로 반복 사용이 적음.

# Idea 012. IKEA AR 조립 보조 (Assembly Helper AR)

## 한 줄 설명
IKEA 가구 조립 시 AR로 부품 위치 시각화 → 스텝별 애니메이션 → 실시간 오류 감지 ("이 부품 역방향입니다").

## 제공하는 Positive Experience

## Target User
IKEA 가구를 구매하는 모든 소비자 (특히 대형 가구).

## 왜 설치하는가
"조립 실패하는 것을 방지" + "조립 시간 단축" 위해.

## 첫 30초
IKEA 가구 모델명 입력 또는 바코드 스캔 → AR 모드 활성화 → 가구 위에 카메라 포인트 → "Step 1: 다리 4개를 준비하세요" 3D 애니메이션 표시.

## 핵심 기능
1. IKEA 가구 데이터베이스 (모델명별 조립 정보)
2. 스마트폰 카메라 기반 AR 시각화 (부품 배치, 각도 표시)
3. 스텝별 애니메이션 (느린 속도로 반복 가능)
4. 오류 감지 (부품 역방향, 나사 빠짐 등 감지)
5. 조립 진행률 추적 (현재 Step 표시)

## 핵심 사용 루프
가구 구매 → 조립 시작 → AR 켜기 → 스텝별로 따라가기 → 오류 시 경고 → 완성 → 사진 공유

# 가장 중요한 관찰

## 1. Performance-Fee 모델의 가치 발견
이번 Pain Signal 분석에서 두드러진 패턴은 "**약속 미충족 시 보상**" 모델의 가능성이다.
- I001 (예약 시간): "30분 초과 시 자동 쿠폰" → 병원이 약속을 지키지 못했을 때만 보상
- I002 (주차보증): "10분 초과 시 배송쿠폰" → 주차장이 약속을 지키지 못했을 때만 보상

기존 시장은 주로 "구독료 모델" 또는 "광고 기반"이었지만, 이 Performance-Fee 모델은:
- 서비스 제공자가 "약속을 지키도록" 동기부여됨 (품질 향상)
- 사용자는 "약속 미충족 시만 비용 부담" 심리로 신뢰도 ↑
- 신규 창업자도 초기 자본이 적게 필요 (실패 리스크 분산)

## 2. 기존 Mainstream 앱 신호의 한계 인식
긍정신호 20개 중 대부분(화해, 무신사, 쿠팡 와우, 야놀자, 마네포ME, YouTube Premium 등)이 "**이미 대성공한 앱**"이다.
단순히 이들의 메커닉을 조합(예: "Duolingo + 무신사 = 패션 스트릭")하는 것은 "X 앱인데 Y 도메인" 반복의 위험.

따라서 이번 I008(마음가는 패션 스트릭)은:
- Duolingo의 "스트릭 손실회피" 메커닉을 추출
- 무신사의 "일일 쿠폰" 메커닉을 추출
- 결합하되, "주간 테마 제약" → "스타일 일관성" → "SNS 공유" 라는 새로운 가치흐름 창출
- 단순 "앱 조합"이 아니라 "새로운 행동 루프" 설계

## 3. Platform Risk 플래깅의 중요성 (CEO 지시 이행)
각 아이디어마다 "Platform Risk" 항목을 명시했다:
- I001: 닥터나우 등이 이미 대기시간 기능
- I007: Google Calendar, Slack이 자체 기능 추가 가능성
- I006: 통신사 자체 앱이 내장할 가능성

이는 사업성 판단(Market Agent 역할)의 입력 데이터로 중요하지만, Manager는 "**제품 품질 자체는 높다**"고 평가하고, Market Agent에게 넘긴다는 의도 명확히 함.

## 4. 점수 보정: Mainstream 앱 "재포장" 에 대한 엄격한 감점
I010(반품배송 자동라벨)과 I012(IKEA AR)는 기술적으로 구현 가능하지만, 점수가 낮은 이유:
- I010: 반복 사용 빈도(4/10), Retention(3/15) → 반품은 "한 달에 1~2회" 정도, 매일 앱을 열지 않음
- I012: Personalization(1/5), MVP 구현 난이도(2/5) → IKEA 데이터 협력이 필수, 1인 개발 불가능

즉, 기술 > 심리 > 비즈니스 가능성 순서로 가치를 평가했고, "좋은 기술이라도 반복 사용 동기가 약하면 C등급"이라는 기준 유지.

## 5. AI의 역할 재정의
대부분의 아이디어에서 AI는 "**정확한 예측**"이 아니라 "**패턴 학습 → 개인화 추천**"이다:
- I006 (데이터 사용량): AI가 "다음주 8.2GB 쓸 거예요"보다는 "당신의 패턴: 평일 저, 주말 고"를 학습
- I007 (타임존): AI가 정확한 겹치는 시간보다는 "팀원별 선호도 학습"
- I008 (패션 스트릭): AI가 "완벽한 코디"보다는 "개인 스타일 + 계절 트렌드" 학습

즉, "AI 없으면 안 되는가"라는 CEO 기준에서, 대부분은 "**AI가 있으면 초기 데이터 부족 문제를 해결하고, 개인화 속도를 높인다**"는 보조 역할로 평가.
